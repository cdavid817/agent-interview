# 题目结构规范

题目使用稳定 ID，而不是依赖文件位置的连续显示编号。稳定 ID 不直接出现在标题中，仅以隐藏锚点形式保留，供跨章节引用与历史别名跳转使用。标题以**文件内顺序号**开头（从 1 递增，便于阅读定位），序号仅用于显示、随文件内容增删而重排，不可作为长期引用。

```markdown
<a id="plan-023"></a>
### 1. Agent 如何判断任务是否需要拆解？

答案正文……

**相关知识点：** Task Decomposition、复杂度评分。
```

## 规则

- ID 由章节前缀和三位数字组成，一经发布不得复用或因移动文件而修改。
- 标题以 `### N. ` 开头，N 为该文件内题目的出现顺序（1、2、3……）；序号只作显示定位，增删题目时由 `python scripts/build_indexes.py` 或重新排序更新，不作为引用凭据。
- 标题只写题目本身，不附带 ID；ID 通过紧邻标题上方的 `<a id="prefix-nnn"></a>` 锚点保留。
- 每个题目只保留一个主归属；跨章节关系使用链接和标签表达，不复制答案。
- 同义问法收录在主问题的“相似问法”，更深入的问题收录为“常见追问”。
- 单个题目文件最多 50 题，文件必须属于一个明确子主题。
- 产品专题（OpenClaw、Claude Code、OpenCode）题目在标题下方保留一行核验日期与来源（指向同目录 references.md），其余章节不展示元数据行；来源标签目前只允许「官方资料」与「源码分析」两种，分别对应产品官方文档与源码逐层分析资料。
- 产品、协议和价格等易变化内容应记录版本或核验日期。
- 修改后运行 `python scripts/validate.py`；涉及术语时再运行术语索引生成脚本。
