# 回答与评分框架

## 推荐回答结构

1. **结论**：先明确推荐方案和适用前提。
2. **机制**：说明输入、状态、关键组件、执行流程和输出。
3. **权衡**：解释为什么这样选，以及被放弃方案何时更合适。
4. **风险**：覆盖失败模式、安全边界、降级和恢复。
5. **指标**：给出正确性、延迟、成本、稳定性或业务效果指标。

## 三级回答深度

- 30 秒：结论、核心机制、一个关键指标。
- 3 分钟：补充流程、组件边界、失败处理和权衡。
- 深入追问：加入规模假设、数据结构、容量估算、灰度方案和复盘案例。

## 自评标准

| 维度 | 合格表现 |
|---|---|
| 相关性 | 直接回答题目，不以术语堆砌代替结论 |
| 正确性 | 区分官方事实、配置能力和设计建议 |
| 工程性 | 有确定性校验、失败处理和可回滚机制 |
| 边界感 | 明确适用条件、不适用场景和安全约束 |
| 可验证性 | 至少给出一个可以采集或复现的指标 |
