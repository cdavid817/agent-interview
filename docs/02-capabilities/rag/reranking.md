### 加权融合和RRF有什么区别？

**加权融合直接组合经过校准的检索分数，RRF只组合各通道排名；前者表达能力更强，后者对异构分数更鲁棒。**

| 维度 | 加权融合 | RRF |
|---|---|---|
| 输入 | 归一化或校准分数 | 候选名次 |
| 公式 | Σw_i·s_i | Σ1/(k+rank_i) |
| 优势 | 可学习通道重要性 | 无需分数校准、稳定 |
| 局限 | 对分布漂移敏感 | 丢失分数间隔信息 |

1. 加权融合保留分数间隔，可设置固定权重，也可由Learning-to-Rank按查询类型学习；但BM25、余弦相似度和业务分数范围不同，必须先做Min-Max、Z-score或分位数校准。数据不足、索引变更或模型升级时，权重容易失效，异常高分还可能支配结果。

2. RRF按候选在各通道中的名次计算倒数排名和，以常数k平滑头部差异。它适合分数不可比、标注有限的场景，对尺度变化和极端值不敏感；代价是忽略分数间隔，也无法表达某一路远强于其他通道。**RRF提供稳健默认值，加权融合提供在可靠数据支持下进一步优化的空间。**

3. 选型应采用相同候选与精排器做消融，比较Recall@K、MRR、nDCG、稳定性、P95时延和答案正确率。数据少、通道常变化时优先RRF；有充足标注、通道差异明确时使用校准加权或学习融合。两者都只负责候选合并，之后仍需去重和Cross-Encoder精排。**上线后必须监控分数分布漂移与通道失效。**

**相关知识点：** 分数融合、RRF、分数校准、Learning to Rank、排名融合、分布漂移、Cross-Encoder、消融实验。

### Rerank模型如何训练？

**Rerank模型应使用与线上分布一致的查询—文档样本，通过点式、对式或列表式目标学习相关性顺序。**

1. 数据来自人工标注、点击日志和成功轨迹，每条查询包含正例、相关例与负例。应从BM25、Embedding或旧Reranker的Top-K中挖掘“接近但不能回答”的困难负样本，并加入错误主体、过期事实、否定冲突和部分覆盖。点击数据需校正位置偏差，防止曝光顺序被当作相关性。

2. Cross-Encoder将query与document拼接输入Transformer。点式用分类或回归损失预测等级；对式用Margin Ranking Loss保证正例高于负例；列表式直接优化同一查询下的排序，更接近nDCG但计算更高。数据不足时可由教师生成软标签并蒸馏。**训练候选必须模拟线上召回器，否则模型会在容易负例上过拟合而无法处理真实噪声。**

3. 验证按查询或时间切分，避免泄漏；离线比较MRR、nDCG、Precision@N、困难负例误排率和校准，在线观察答案正确率、P95时延与成本。按语言、主题和风险分桶，并保留无Rerank基线。上线采用版本化、回放和灰度，将可信纠错加入主动学习。**若Recall@K不足，应先修复召回，Reranker无法学习未进入候选的证据。**

**历史别名：** `RAG-078`。

**相关知识点：** Cross-Encoder、点式学习、对式学习、列表式学习、Margin Ranking Loss、困难负样本、位置偏差、知识蒸馏、nDCG、主动学习。

### Rerank带来的性能开销如何解决？

**Rerank性能优化应遵循“减少候选、降低单对成本、提高硬件利用率、设置可降级边界”，同时守住排序质量下限。**

1. 先压缩精排候选：召回阶段应用ACL、时间和版本过滤，混合候选经RRF后去重，并用分数阈值、动态K或轻量模型淘汰无关项。精确实体查询可跳过昂贵Reranker，模糊或高风险查询扩大候选。**减少无效查询—文档对通常比盲目优化模型算子更直接，因为Cross-Encoder成本随候选数和序列长度增长。**

2. 推理侧选用蒸馏或量化的小型Cross-Encoder，限制文档长度并保留高信息片段；将候选组成批次，启用动态Batch、混合精度和GPU并行。可采用两级精排：轻模型处理Top-K，重模型只处理边界不明确的Top-M；头部分数领先时早停。缓存键包含query、document_version、model_version和ACL，防止跨版本或越权复用。

3. 系统侧设置并发上限、超时、熔断和背压，超时后降级为融合排序或更小N。离线绘制候选数、模型大小、长度与MRR、nDCG的关系，在线监控P95/P99、GPU利用率、队列时间、超时率、答案正确率和单位成本。通过影子流量与A/B验证优化，避免损害长尾查询。**目标是质量—时延—成本的帕累托最优。**

**相关知识点：** Cross-Encoder、级联重排、模型蒸馏、量化、动态Batch、早停、缓存键、熔断、背压、帕累托最优。

### Rerank带来的延迟如何优化？

**Rerank延迟优化的核心是在不显著损失排序质量的前提下，减少候选数量、单次计算量与无效等待。**

1. 先拆分召回、排队、模型推理和网络耗时，按查询类型统计P50、P95与候选规模。采用两阶段裁剪：召回Top-100后用Bi-Encoder预筛至Top-20，再交给Cross-Encoder；高置信结果可跳过精排。候选上限应由离线Recall@K曲线确定，不能只按延迟目标拍定。

2. 模型侧可选择更小的Cross-Encoder、缩短query与document最大长度、动态截断低信息段，并采用FP16、INT8量化、蒸馏和编译优化。服务侧将同批候选组成动态Batch，使用GPU并发、固定形状分桶与异步流水线提升吞吐。**不能只比较单请求推理时间，还要同时观察批处理等待、吞吐饱和点及排序指标下降。**对极长文档可先抽取标题、摘要和命中窗口再打分。

3. 对稳定知识版本缓存精排结果，缓存键包含租户、权限、模型、索引版本与候选集合摘要；超时后返回召回排序。离线验证nDCG、MRR和困难负例误排率，在线比较正确率、P95、GPU利用率与成本。若目标证据掉出最终Top-N，应回调候选规模或恢复完整精排。

**相关知识点：** Cross-Encoder、级联排序、动态Batch、模型蒸馏、INT8量化、候选裁剪、超时降级、nDCG、P95、排序缓存。

### Re-ranking 的作用是什么？

**Re-ranking的作用是对高召回、低精度的候选做细粒度查询—文档匹配，把最可回答当前问题的证据排到前部。**

1. BM25和Bi-Encoder为效率通常独立编码查询与文档，只能用词项或向量近邻做粗筛，容易召回主题相似但不含答案、实体错误、版本过期或否定相反的内容。Cross-Encoder同时读取query和candidate，可识别词间交互、条件与答案对应关系。它不能找回未进入候选池的证据，因此前置Recall@K仍是上限。

2. 生产排序除语义相关性外，还可融合权威性、时效、文档版本、业务优先级和多样性；tenant_id、ACL等安全条件必须在精排前硬过滤。**Re-ranking优化“候选顺序和最终精度”，召回优化“正确证据能否进入候选”，二者职责不能互换。**精排后再按文档与语义去重，选择有限Top-N进入压缩。

3. 训练负例应来自线上召回Top-K，覆盖相似无答案、过期、错实体和反义候选；随机负例只能补充。离线比较MRR、nDCG、Precision@N及困难负例误排率，在线观察答案正确率、引用命中、P95和成本。为控制延迟，可用候选裁剪、小模型、蒸馏、量化和动态Batch，低风险高置信查询允许跳过精排。

**相关知识点：** Retriever、Re-ranker、Bi-Encoder、Cross-Encoder、Recall@K、MRR、nDCG、困难负例、级联排序、知识蒸馏、动态Batch。

### Contextual Compression 是怎么实现的？

**Contextual Compression以当前查询为条件，从已召回文档中筛选或抽取能直接支撑回答的证据，而不是生成与查询无关的通用摘要。**

1. 流程先对召回候选执行ACL、版本、时效过滤和Rerank，再将高排名文档按句子、段落或表格行划分为可定位片段；以query和片段计算相关性，删除无关片段。最稳妥的是抽取式压缩，原文不被改写；长文也可先用小模型判断保留区间，再合并邻接片段，避免证据被切断。

2. 生成式压缩可让模型按查询重述证据，压缩率高但可能遗漏否定、数字或引入幻觉，因此必须保存document_id、页码、字符区间和原文引用，并对关键字段做一致性校验。**Rerank决定哪些文档优先，Contextual Compression决定这些文档中哪些内容进入Prompt，两步都需要但目标不同。**

3. 多文档结果先按来源和语义去重，冲突片段成组保留并标注，最终在Token预算内选择覆盖各子问题的最小证据集。评测压缩率、证据Recall、引用保持率、事实一致性、答案忠实度、P95和额外模型成本；构造数字、否定、表格及代码样本。压缩后证据不足时，应扩大区间或回退原文，而不是让生成模型补全。

**相关知识点：** Contextual Compression、查询条件压缩、抽取式压缩、生成式压缩、证据区间、引用保持率、事实一致性、Rerank、邻接合并、原文回退。

### 为什么需要 Rerank？

**向量召回采用双塔独立编码，只能近似衡量语义；Rerank联合建模查询与候选，可修正误召回、提高前列精度并减少注入Prompt的噪声。**

1. Retriever为高吞吐需提前编码文档，用BM25或向量距离快速取候选，难以判断是否真正回答问题。主题相似但无答案、实体错位、版本过期、数字不同和否定相反的Chunk仍可能高分。Cross-Encoder共同输入query与candidate，建模词间交互、限定条件和答案位置，提高前列Precision。

2. 在混合检索中，BM25和向量分数空间不同，RRF只完成粗融合；Rerank可统一评估相关性，并融合来源权威性、时效、多样性和业务规则。**Rerank不能找回未进入候选池的证据，因此召回Recall@K是上限，精排负责改善顺序与最终Top-N精度。**权限和租户条件仍需前置硬过滤。

3. 训练使用线上Top-K的困难负例，离线看MRR、nDCG、Precision@N和反义误排率，在线看正确率、引用、P95与成本。Rerank延迟可通过候选裁剪、小模型、蒸馏、量化和Batch优化。若精排未提升端到端任务或召回已精准，应评估是否保留。

**相关知识点：** Retriever、Rerank、Bi-Encoder、Cross-Encoder、RRF、困难负例、Recall@K、Precision@N、nDCG、知识蒸馏、动态Batch。

### 如何实现动态权重调整而非固定权重？

**动态权重应由查询特征和候选质量实时决定，使BM25、向量、图检索及业务信号针对不同问题分配不同贡献，而不是共享一组全局常量。**

1. 先构造可解释特征：查询长度、稀有词比例、实体与数字数量、是否包含错误码或文件路径、语言、意图类别、各路Top-1分数、分数间隔及候选重合度。规则基线可在精确标识符查询中提高BM25权重，在自然语言描述中提高向量权重，多跳关系问题提高图检索权重；分数须先归一化，否则原始量纲差异会使权重失真。

2. 有标注数据时可训练Learning to Rank、门控网络或多臂老虎机，输入查询与候选特征，输出通道权重或直接预测最终相关性；标签来自人工等级、点击后任务完成和失败样本。**动态调权的目标是提升最终排序质量，不是让模型自由产生不可约束的任意系数。**因此权重需限制范围、和为一，并保留默认策略和低置信度回退。

3. 离线按查询类型比较固定权重、规则动态和学习动态三组的Recall@K、MRR、nDCG与稳定性，并通过消融确认特征贡献；线上采用小流量A/B或交错实验，设置权限、P95和成本护栏。Trace记录特征、模型版本、实际权重、各路候选和最终排名，监控权重分布漂移；策略退化时可立即切回RRF或固定权重基线。

**相关知识点：** 分数归一化、查询分类、Learning to Rank、门控网络、多臂老虎机、RRF、特征消融、分布漂移、策略回退。

### 如果用户问题关联多个知识库，Prompt 如何动态组装？

**多知识库Prompt应先按意图与权限路由检索，再统一精排、去重和分配Token预算，最终以带来源标签的最小充分证据组装，而不是逐库拼接Top-K。**

1. 查询路由器依据用户身份、业务域、实体、语言和问题类型选择允许访问的知识库，并生成相同的时间与版本约束；可并行召回，但每条候选必须保留knowledge_base_id、document_id、ACL、权威等级和更新时间。若路由置信度低，可搜索多个库；禁止为了提高召回而绕过库级授权。

2. 各库分数先校准或以RRF融合，再用统一Rerank结合相关性、权威性、时效和来源多样性排序；按同文档和语义去重，并为每个必要知识域保留最低配额。**Token预算应按回答所需证据价值动态分配，而不是平均分给每个知识库。**库间冲突时保留双方证据、生效时间与优先级，交给明确规则裁决。

3. Prompt Builder先放系统指令、当前问题与回答格式，再按逻辑主题分组注入证据，每块使用不可伪造的来源ID、标题、时间和引用位置；长片段做抽取式压缩，保留数字、否定及适用范围。若证据不足，触发二次检索而非填满窗口。评估包括跨库证据覆盖率、冲突处理正确率、引用准确率、Faithfulness、Token成本和权限越界率。

**相关知识点：** 查询路由、库级ACL、RRF、跨库Rerank、Token配额、来源多样性、冲突消解、证据分组、引用溯源。
<a id="rag-167"></a>
### 如何评估Rerank模型的效果？

**Rerank效果应在固定召回候选上比较排序前后的前排质量、正确证据保留率、端到端回答收益及新增延迟，不能只看模型离线分类准确率。**

1. 构建查询—候选—相关性等级数据，候选必须来自真实BM25、向量和混合召回，并包含词面相似、实体错误、过期版本等难负例；固定候选集、语料快照和Top-K，避免召回变化干扰归因。按实体、语义、多跳、长尾和无答案查询分层，训练、调参与测试按查询或文档隔离。

2. 离线比较Rerank前后的MRR、nDCG@K、Precision@K、首个相关结果排名和完整证据集合保留率，并观察不同候选规模的增益。**Rerank只能重新排列已有候选，评测时必须区分召回缺失与排序错误。**还要检查同源重复、时效、权限及分数校准，防止语义相关却不可用的文档进入前排。

3. 性能侧统计每候选推理耗时、批量吞吐、P95、GPU利用率和成本，绘制nDCG—Latency曲线；端到端固定Prompt与生成模型，比较答案正确率、Faithfulness和引用准确率。上线采用A/B或交错实验，主指标为任务成功，延迟与成本作护栏。通过无Rerank、旧模型、新模型消融，确认收益足以覆盖新增计算。

**相关知识点：** Rerank、难负例、MRR、nDCG@K、Precision@K、证据集合保留率、Cross Encoder、消融实验、交错实验。
<a id="rag-183"></a>
### Prompt 与 RAG 的边界在哪里？

**Prompt规定模型如何工作及如何使用证据，RAG负责在调用前找到哪些外部事实应进入上下文，二者分别承担行为约束与知识供给。**

1. Prompt承载目标、流程、输出Schema、工具规则、安全边界和证据使用方法，并受版本控制；RAG处理文档、数据及政策等外部知识，通过查询改写、召回、重排和过滤产生所需证据。**高频变化或规模较大的事实应进入RAG，稳定且必须执行的规则应进入Prompt。**

2. 两者在Prompt Builder处衔接：先固定高优先级约束，再将结果作为带source、version、score与ACL的证据块注入，并明确证据不能修改指令。检索为空、证据冲突或置信度不足时，应澄清、重新检索或输出不确定性，不能用参数记忆补齐缺口。

| 组件 | 主要职责 | 主要产物 |
| --- | --- | --- |
| Prompt | 定义行为、权限与格式 | 可测试的指令模板 |
| RAG | 提供新鲜、可授权的事实 | 可追溯证据集合 |

3. **边界治理应分别评测指令遵循与检索质量，再以任务成功率验证组合效果。**Prompt侧检查越权率、格式通过率和工具误用率；RAG侧检查Recall@K、NDCG、新鲜度、权限泄漏率及引用准确率。回答错误时，应区分未召回、重排错误、注入失败还是模型未遵循证据，避免用堆叠Prompt掩盖检索缺陷。

**相关知识点：** Prompt Engineering、RAG、Prompt Builder、查询改写、重排、证据边界、指令优先级、Recall@K、NDCG、引用准确率。
<a id="rag-196"></a>
### 如何训练高质量 Reranker，难负例从哪里来？（高级）

**Reranker质量主要取决于与线上候选分布一致的正负样本，尤其是“主题相关但不能回答”的难负例，而不是随机负例数量。**

1. 正例应标注最小充分证据和适用版本；难负例可来自BM25/向量Top结果、同产品不同版本、同实体不同属性、近义但条件不符的片段，以及线上被召回却导致错误的候选。避免把未标注的潜在正例误作负例。
2. 训练可用pointwise、pairwise或listwise目标，数据按文档、时间和用户域切分，防止相邻Chunk泄漏。蒸馏标签需人工校准，且保留真实无答案与多证据样本。
3. 评估除MRR、NDCG外，还要测充分证据Top-N覆盖、无答案误选率、跨域泛化、P95和吞吐；上线采用小流量灰度，持续从已确认失败中挖掘难负例而不污染测试集。

**相关知识点：** Hard Negative Mining、Cross Encoder、Pairwise Ranking、Listwise Loss、False Negative、数据泄漏、Online Mining。
