### Agent如何判断是否需要Web Search？

**当问题要求外部、实时或内部知识库未覆盖的信息，且来源可验证时才使用Web Search；稳定内部事实应优先使用受控知识库。**

1. Web Gate识别“最新、当前价格、政策、新闻、官网、近期版本”等时效或外部要求，并检查上下文的source、published_at和freshness SLA。用户明确要求搜索、需要引用网页、内部库无覆盖或证据不足时触发；企业私有数据、用户记忆和稳定制度应查询授权系统，不能上传公开搜索。

2. 触发后生成去除敏感信息的搜索查询，限制域名、语言、时间范围和最大轮次；优先官方、原始和多源可交叉验证的页面，记录URL、发布日期、抓取时间与摘要。**搜索结果是外部不可信数据，网页中的指令不得改变System策略或工具权限，引用内容也不能自动写入长期记忆。**高风险事实需至少两个独立来源或权威主源。

3. 评测覆盖需搜索、无需搜索、内部优先、敏感查询、时效过期和无可靠来源，统计触发Precision/Recall、来源权威率、引用正确率、任务成功、P95和成本。记录触发理由、查询改写和采用来源；低置信时先搜元数据再决定读取正文。达到预算仍无证据时说明不确定性。

**相关知识点：** Web Gate、Freshness SLA、搜索意图、敏感信息最小化、来源权威性、交叉验证、间接Prompt Injection、引用正确率、搜索预算、反事实评估。

### Recall@K、MRR、NDCG 分别衡量什么？

**Recall@K衡量前K项覆盖了多少相关结果，MRR关注首个相关结果的倒数排名，NDCG同时评价多级相关性与整体排序位置。**

1. Recall@K等于前K项命中的相关结果数除以该查询全部相关结果数，回答“正确证据是否被召回”。RAG中若只要求至少一条证据，还可统计Hit@K；多跳问题应改用完整证据集合覆盖率。Recall随着K通常单调增加，却不惩罚大量无关候选，因此不能单独说明前排质量或上下文噪声。

2. MRR取首个相关结果排名的倒数并对查询平均；第1名得1，第2名得0.5，适合单答案任务。**MRR忽略第二个及后续相关结果，即使其他证据排序很差，只要首个命中相同，分数也不会变化。**

| 指标 | 衡量重点 | 适用判断 |
| --- | --- | --- |
| Recall@K | 前K项覆盖相关结果的比例 | 是否漏召回 |
| MRR | 首个相关结果的排名 | 首条命中是否靠前 |
| NDCG | 多级相关结果的整体排序 | 排序质量是否合理 |

3. NDCG按相关性等级计算DCG，位置越靠后折损越大，再除以IDCG归一化到0—1，适合多个结果且有相关等级的排序任务。三项指标必须基于同一语料快照和完整标注，按查询类型报告，并结合Precision@K、延迟与端到端答案质量；扩大K可能提高Recall，却增加Rerank和Prompt成本。

**相关知识点：** Recall@K、Hit@K、证据集合覆盖率、Reciprocal Rank、MRR、DCG、IDCG、nDCG、Precision@K。

### Recall@K、MRR、NDCG分别适用于什么场景？

**候选召回优先使用Recall@K，首个结果决定体验的单答案任务使用MRR，多级相关的列表排序与Rerank使用NDCG。**

1. Recall@K适合候选召回，尤其是RAG、多路检索和一个问题有多条证据的场景，回答“相关材料是否进入前K项”。若只要求命中一条，可用Hit@K；多跳问题看完整证据集合覆盖率。Recall随K增加，不惩罚无关候选，因此不能衡量上下文噪声。

2. MRR适合导航搜索、FAQ和首个结果决定体验的单答案任务；它只取第一条相关结果排名倒数，第1名为1、第2名为0.5。**MRR对第二条及后续正确结果不敏感，因此不适合需要多份证据或完整列表的任务。**首命中相同的系统即使后续排序差异很大，MRR也可能相同。

| 指标 | 更适合的场景 | 关注重点 |
| --- | --- | --- |
| Recall@K | 候选召回、答案可能多源 | 证据覆盖率 |
| MRR | 导航搜索、首个答案最重要 | 首次命中位置 |
| NDCG | 多级相关性、结果列表排序 | 列表排序质量 |

3. nDCG适合电商、搜索列表和Rerank等有多个结果与相关等级的场景，它奖励高相关结果靠前并对位置折损，再用理想排序归一化。三项指标须在同一语料快照与标注下计算，按查询类型分层，并结合Precision@K、P95和答案质量，避免扩大K获得表面Recall却增加噪声与成本。

**相关知识点：** Recall@K、Hit@K、证据集合覆盖率、Reciprocal Rank、MRR、DCG、IDCG、nDCG、Precision@K。

### 没有标准答案时如何评估RAG效果？

**没有唯一标准答案时，应从证据充分性、回答忠实度、任务约束满足和用户结果四个层面评估，而不是依赖字符串匹配。**

1. 即使没有参考答案，也可标注问题所需的证据、关键事实、禁止错误和评分Rubric。检索侧由专家判断Top-K是否包含最小充分证据，统计证据命中、完整集合覆盖、相关性和噪声；生成侧逐条核对陈述能否由给定证据支持，评价Faithfulness、引用准确率、完整性、拒答合理性与格式约束。

2. LLM-as-a-Judge可根据问题、证据和Rubric做分项或成对比较，适合开放式总结与多种等价表达；必须隐藏系统身份、随机交换候选顺序，并用人工样本校准一致性、位置偏差和自偏好。**Judge只能扩展人工标准，不能把自身判断自动当作事实真值。**安全、引用和结构化格式尽量使用确定性检查器。

3. 线上用任务完成率、用户纠错、追问率、人工转接、引用点击和投诉衡量真实价值，并通过稳定分桶A/B比较策略；高风险领域进行专家抽样审计。评估报告按查询类型、证据是否充分和有无答案分层，同时记录P95与单位成功成本。若证据不充分，系统正确拒答应得高分，不能被“回答更长”错误奖励。

**相关知识点：** Rubric、最小充分证据、Faithfulness、引用准确率、成对比较、LLM-as-a-Judge、人工抽样、任务成功率。

### 如何量化RAG系统的幻觉率？

**RAG幻觉率应定义为回答中无法被授权证据支持、与证据矛盾或捏造来源的事实陈述占比，并同时报告答案级与声明级指标。**

1. 先把答案拆成可验证的原子声明，对每条声明标记Supported、Contradicted、Not-in-Evidence或Not-Verifiable，并记录对应证据ID。声明级幻觉率为矛盾与无依据声明数除以全部事实声明数；答案级幻觉率为至少包含一条幻觉的答案比例。引用不存在、引用与陈述不对应和伪造页码应单独统计，避免被总体平均掩盖。

2. 样本覆盖有答案、无答案、多跳、冲突版本、长上下文和对抗问题；Judge只能依据提供证据判定，不能调用参数知识补全。可用NLI或LLM-as-a-Judge扩展规模，但需由专家标注集校准精确率、召回率与阈值。**检索不到证据后模型仍强答是幻觉，正确拒答不应计入幻觉；答案错误但证据本身错误则归为知识质量问题。**

3. 报告按严重度、查询类型和证据充分度分层，使用风险加权幻觉率反映高风险事实；同时观察Faithfulness、拒答率和答案覆盖，防止通过大量拒答降低幻觉。线上抽样结合用户纠错、引用投诉和人工审计，Trace保留候选、Prompt与版本。变更模型、Prompt或检索后在同一快照回归，并给出置信区间。

**相关知识点：** 原子声明、声明级幻觉率、答案级幻觉率、Faithfulness、NLI、LLM-as-a-Judge、引用准确率、风险加权、正确拒答。

### 如何评估知识库覆盖率？

**知识库覆盖率应衡量真实问题是否存在可访问、有效且足以回答的证据，并与检索能否找到该证据分开统计。**

1. 从脱敏查询日志、工单、专家题库和失败样本构建代表性问题集，按业务域、意图、产品、语言、地区、时间敏感度与用户权限分层。对每个问题人工判断知识库中是否存在最小充分证据、是否在有效期且该用户可访问；覆盖率等于有充分证据的问题数除以全部目标问题数，必要时按业务流量或风险加权。

2. 将失败拆为知识缺失、文档过期、权限不可达、证据不完整、检索未命中和生成未使用。**“库中有文档”不等于知识已覆盖，只有内容包含回答所需事实且处于正确版本和权限域才算有效覆盖。**多跳问题要求完整证据集合，重复文档数量不能提高覆盖率；无答案问题则检查系统是否具备明确拒答依据。

3. 输出总体、流量加权、风险加权和各切片覆盖率，并维护“问题—证据—责任数据源”矩阵，按缺口影响排序补录。线上监控无结果、正确拒答、用户纠错和人工转接，但这些只作代理指标，需抽样复核。文档更新后自动标记受影响样本重评，结合Recall@K区分知识建设问题与检索算法问题。

**相关知识点：** 知识覆盖率、最小充分证据、流量加权、风险加权、权限可达性、多跳证据、缺口矩阵、Recall@K。

### 企业级RAG系统最关键的三个指标是什么？

**企业级RAG最关键的三个指标是任务成功率、证据忠实度和单位成功任务成本；权限越界率应作为独立的零容忍安全门禁。**

1. 任务成功率衡量用户目标是否完成，例如首次解决、正确操作、工单闭环或专家判定通过；它把检索、生成和工具协同后的真实业务结果纳入同一口径，比点赞或文本相似度更接近价值。定义时必须明确任务、成功条件、观察窗口和无答案时的正确拒答，并按场景与风险分层。

2. 证据忠实度衡量答案事实是否被检索证据支持，可通过原子声明归因、引用准确率和幻觉率组合观察。**任务暂时成功也不能掩盖无依据答案，因为不可审计的正确猜测在企业环境中仍是风险。**同时保留Recall@K作为诊断指标：忠实度低需查生成，证据未召回则查知识与检索。

3. 单位成功任务成本将Token、Embedding、检索、Rerank、工具和基础设施费用除以成功任务数，能防止用无限候选与大模型堆出不可持续质量；P95作为SLO护栏纳入成本效率分析。安全方面，任何ACL越权、敏感泄露和错误高风险动作均不能被三项平均指标抵消，应独立阻断发布并触发审计。

**相关知识点：** 任务成功率、Faithfulness、引用准确率、幻觉率、单位成功任务成本、Recall@K、P95、权限越界率、安全门禁。
