### Skill如何支持参数化和动态配置？

Skill应通过**稳定契约承载业务参数，通过受控配置承载环境与策略差异**，并将两者与实现版本分离；动态不等于允许任意Prompt或权限在运行时被修改。

1. **参数契约**：使用JSON Schema定义类型、必填、枚举、默认值、范围、互斥和敏感标记，区分用户输入、系统派生值和运行时上下文。参数标准化后再校验，禁止未声明字段透传给Tool。
2. **配置分层**：平台默认、环境、租户、Skill版本和会话覆盖按明确优先级合并；权限、风险阈值等安全配置只能收紧，不能被低层覆盖放宽。密钥仅保存引用，由运行时按身份注入。
3. **动态加载**：配置中心提供版本、Schema、签名、灰度和推送机制；任务启动时生成不可变配置快照并记录版本，运行中不随全局配置漂移。紧急撤销可中止任务，但需明确审计。
4. **表达能力**：简单差异用参数，有限业务差异用声明式条件和策略表，复杂流程差异使用版本化Workflow；避免在配置中嵌入任意代码，防止验证、调试和安全边界失控。

| 变化类型 | 推荐载体 | 示例 |
|---|---|---|
| 任务输入 | 参数 | 日期、目标资源 |
| 租户偏好 | 动态配置 | 语言、额度 |
| 安全规则 | Policy | 权限、审批阈值 |
| 执行逻辑变化 | Skill新版本 | 新分支、新Tool |

通过契约测试、配置组合测试和灰度指标验证更新，并限制参数基数、配置层级与废弃字段，避免长期兼容负担。

**相关知识点：** JSON Schema、配置分层、不可变快照、配置中心、策略即代码、Secret引用、灰度配置、契约测试、配置漂移。

### 如何评估Skill的效果和ROI？

Skill评估应同时衡量**任务质量、效率、风险和经济收益**，并与“无Skill、人工流程或旧版本”基线比较；调用量增长本身不代表产生价值。

1. **质量指标**：在代表性任务集上测端到端完成率、输出正确率、参数一次通过率、用户接受率、人工纠正率和稳定性；按任务难度、租户与风险切片，严重错误采用更高权重。
2. **效率指标**：记录完成时长、人工操作分钟数、步骤数、Tool调用数、Token、模型与基础设施费用，以及重试和审批等待。关注一次成功成本，避免表面单次便宜却因重试提高总成本。
3. **风险指标**：衡量越权拦截、误调用、敏感数据暴露、重复副作用、人工接管和安全事件；高风险Skill还需计算风险调整收益，任何不可接受事故都可触发下线。
4. **ROI计算**：周期净收益等于节省人工成本、业务增量与风险损失减少之和，减去开发、评测、运行、维护及治理成本；ROI为净收益除以总投入，并结合回收期判断。

| 维度 | 代表指标 | 对照基线 |
|---|---|---|
| 质量 | 成功率、纠正率 | 无Skill/旧版 |
| 效率 | 时长、一次成功成本 | 人工流程 |
| 风险 | 事故率、接管率 | 原控制方案 |
| 经济 | 净收益、回收期 | 总拥有成本 |

采用A/B、影子或分阶段对照，控制任务分布差异；上线后持续复评，若使用率低、无显著增益或维护成本上升，应优化、合并或下线。

**相关知识点：** ROI、总拥有成本、基线对照、A/B测试、风险调整收益、一次成功成本、回收期、端到端评测。

### Skill调用失败后如何降级处理？

Skill降级应依据**失败类型、已产生副作用和业务最低可接受结果**选择路径，目标是安全地保留已有进展，而不是无条件换Skill重试。

1. **识别失败**：区分输入缺失、前置条件不满足、模型错误、Tool瞬时故障、权限拒绝、质量校验失败和预算耗尽；失败事件返回结构化错误码、可恢复标志、检查点及已完成副作用。
2. **分层策略**：瞬时故障可有限退避重试；主模型不可用可切换已评测的备用模型；可选Tool失败时使用缓存、等价只读源或部分结果；输入不足则追问用户；权限与安全失败直接终止。
3. **状态安全**：写操作使用幂等键并查询真实状态，未确认结果前禁止重复执行；部分完成时按Workflow执行续作或Saga补偿。替代Skill必须接受当前状态并重新授权，不能从头制造重复副作用。
4. **体验与治理**：向用户明确标注降级、数据时效和未完成项；高价值任务转人工并附证据包。设置降级次数、总时限和成本上限，防止在多个Skill之间循环。

| 降级方式 | 适用条件 | 限制 |
|---|---|---|
| 重试 | 瞬时且幂等 | 次数和总时限 |
| 备用实现 | 已通过等价评测 | 能力可能降低 |
| 部分结果 | 非关键步骤失败 | 明示缺失内容 |
| 人工接管 | 高风险或状态不明 | 提供完整上下文 |

监控降级触发率、降级后成功率、重复副作用和用户接受率；长期高频降级应视为产品缺陷而非正常路径。

**相关知识点：** 错误分类、Fallback、幂等、检查点、Saga补偿、部分结果、人工接管、备用模型、降级循环检测。

### Skill Selection 的评估指标有哪些？

Skill Selection需按**候选召回、最终排序、拒选校准、安全损失和业务结果**分层评估，不能用一个准确率概括整条选择链路。

1. **召回层**：Recall@K衡量正确Skill是否进入候选；Candidate Coverage衡量可回答请求中有候选的比例；平均候选数反映后续成本。正确项未召回时，重排再强也无效。
2. **排序层**：Top-1 Accuracy或Precision衡量首选正确性；MRR衡量首个正确项位置；NDCG适合多个Skill均可接受且相关度不同的场景；混淆矩阵定位相似能力竞争。
3. **门控层**：统计无匹配识别率、误拒率、低置信澄清率，并用可靠性曲线、ECE或Brier Score评估置信是否校准；高风险类别单独设置阈值。
4. **风险与业务层**：严重误路由率、越权候选率、用户改选率、人工接管率、端到端任务成功率、一次成功成本、P95延迟及用户满意度共同反映实际价值。

| 指标 | 所属层 | 优化方向 |
|---|---|---|
| Recall@K | 召回 | 越高越好 |
| MRR/NDCG | 排序 | 越高越好 |
| 误拒率 | 门控 | 在风险约束下降低 |
| 严重误路由率 | 安全 | 接近零 |
| 任务成功率 | 业务 | 综合提升 |

指标应按领域、语言、风险、租户、新旧Skill切片，并以风险加权损失确定上线门禁；稳定回归集与真实流量灰度缺一不可。

**相关知识点：** Recall@K、Top-1 Precision、MRR、NDCG、ECE、Brier Score、混淆矩阵、风险加权损失、端到端成功率。

### 如何避免 Skill 数量爆炸？

避免数量爆炸要建立**新增准入、复用优先、分层组合、重复检测和退出清理**机制，使Skill以能力边界而不是个别案例为单位增长。

1. **新增门槛**：提交复用数据、目标边界、契约、评测、Owner和维护预算；Registry自动检索相似描述、Schema与工具序列。若既有Skill能通过参数或策略扩展，默认不批准新建。
2. **抽象分层**：把共性沉淀为基础Skill或子流程，把领域差异放在配置和策略中，业务Skill通过组合复用；同时限制继承和嵌套深度，避免为追求抽象产生大量中间层。
3. **命名与分类**：使用稳定领域树、标签词表、别名和适用/禁用条件，防止不同团队用不同名称重复建设；跨部门公共能力由共享团队维护，领域能力由业务Owner负责。
4. **健康度治理**：按调用量、独立用户、成功率、复用率、改选率、成本、重复命中和维护活跃度评分；低价值项进入观察、合并、弃用、归档流程，清退提供替代映射和迁移期限。

| 根因 | 对策 | 结果 |
|---|---|---|
| 参数差异 | 配置化 | 一个Skill多场景 |
| 流程局部重复 | 子Skill/公共节点 | 降低复制 |
| 跨团队重复 | 语义检测+评审 | 合并资产 |
| 历史版本堆积 | 支持窗口+归档 | 缩小活跃目录 |

Router只加载当前租户和任务所需的活跃子集，也能降低大目录带来的召回竞争，但不能替代源头治理。

**相关知识点：** Skill准入、参数化、能力分层、重复检测、健康度评分、生命周期、弃用归档、别名迁移、活跃子集。

### 如何评估一个 Skill 的使用价值？

Skill使用价值应看**真实采用、增量质量、效率收益、风险改善和长期维护成本**，并与没有该Skill时的流程比较，而非只统计调用次数。

1. **采用价值**：观察活跃用户、覆盖团队、调用频率、复用场景、重复使用率和自然留存；区分自动路由调用与用户主动选择，排除测试流量和循环调用造成的虚假繁荣。
2. **效果增量**：用A/B、影子或前后对照比较任务完成率、正确率、人工纠正、满意度和稳定性；按任务难度切片，确认收益来自Skill而非流量结构或模型升级。
3. **效率与经济**：计算节省人工分钟、缩短交付周期、业务增量和风险损失减少，减去模型、Tool、基础设施、开发、评测、维护与审批成本，关注一次成功成本和回收期。
4. **治理价值**：评估是否统一了权限、审计、SOP和异常处理，是否降低严重误操作、合规缺陷与人员经验依赖。低频高风险Skill可能经济收益不高，但治理价值显著。
5. **生命周期决策**：设置保留、优化、合并和下线阈值；连续周期低采用、无增益、成本上升或无人维护时进入清退。

| 维度 | 代表指标 | 常见误区 |
|---|---|---|
| 采用 | 活跃用户、复用率 | 把调用量当价值 |
| 质量 | 增量成功率 | 无基线比较 |
| 效率 | 时间、一次成功成本 | 忽略重试 |
| 风险 | 事故率、审计覆盖 | 只算直接收入 |

最终形成风险调整后的净价值评分，但保留原始指标，避免单一综合分掩盖严重安全问题。

**相关知识点：** 增量价值、A/B测试、一次成功成本、TCO、回收期、治理价值、风险调整收益、生命周期门槛。

### Episodic Memory 如何转化为 Skill？

Episodic Memory转化为Skill，本质是把**多个具体事件归纳为可复用、可验证的程序性知识**，必须经过聚类、抽象、去隐私和质量门禁。

1. **筛选事件**：选择目标明确、结果经外部验证、用户确认且无越权的成功事件，保留任务、步骤、工具、环境、结果和修正；排除偶然成功、重试循环、人工暗补和已过期规则。
2. **跨事件归纳**：按目标和输出语义聚类，比较多个用户、时间和环境的轨迹，找出稳定步骤、可变参数、前置条件、分支、失败模式和终止状态；单条事件只能作为候选样例。
3. **形成契约**：将实例值替换为Schema变量，定义Skill目标、适用与禁用条件、输入输出、依赖、权限、风险、验证、超时、重试和补偿；去除个人数据和无关上下文。
4. **验证泛化**：在未参与归纳的事件、反例和边界案例上重放，与无Skill基线比较成功率、成本和安全；检查是否把历史偏差、环境特例或过时政策固化。
5. **审核运营**：领域与安全人员批准后版本化、签名并灰度；建立Skill到来源事件、评测集和规则版本的血缘，线上退化时可定位并撤销。

| 阶段 | 输入 | 输出 |
|---|---|---|
| Episodic | 具体事件 | 带来源轨迹 |
| 聚类归纳 | 多条轨迹 | 稳定模式 |
| 契约化 | 模式与变量 | 候选Skill |
| 验证发布 | 独立样例 | 正式版本 |

**相关知识点：** Episodic Memory、程序性知识、轨迹聚类、参数抽象、数据血缘、独立验证、反例、Skill蒸馏、人工门禁。

### 长期记忆是否可以直接生成 Skill？

长期记忆**不能直接生成并发布Skill**。它可以提供候选事实和经验，但其中包含个体偏好、过时信息、错误归因与敏感数据，必须经过抽象和治理。

1. **信息性质不同**：长期记忆回答“某用户或过去发生了什么”，通常带主体、时间和来源；Skill回答“一类任务应如何完成”，要求跨案例有效、目标与步骤稳定。实例记忆不能天然代表通用规律。
2. **主要风险**：单次成功可能是偶然，用户纠正可能只适用于个人；记忆还可能被提示词注入污染、与新政策冲突或已过期。直接Skill化会放大偏差，并把隐私传播到其他任务。
3. **转化流程**：只选择来源可信、结果验证的候选记忆，跨用户与时间聚类；抽取共同目标、变量、步骤、前置条件和失败模式，完成脱敏、冲突检测与时效校验，再生成候选契约。
4. **发布门禁**：候选Skill在独立任务集、反例、权限和故障场景中评测，由领域与安全人员批准后版本化、灰度；高风险领域禁止全自动晋级。
5. **持续血缘**：保存Skill与来源记忆、规则和评测的关系；来源被更正、删除或过期时触发影响分析，而非自动覆盖已发布版本。

| 转化方式 | 是否可行 | 条件 |
|---|---|---|
| 单条记忆直接发布 | 否 | 缺少泛化与验证 |
| 多记忆生成候选 | 是 | 聚类、脱敏、抽象 |
| 候选自动上线 | 谨慎/高风险禁止 | 必须质量门禁 |
| 记忆作个性化参数 | 是 | 用户隔离与授权 |

**相关知识点：** 长期记忆、经验泛化、提示词注入污染、数据脱敏、冲突检测、时效性、Skill候选、人工审核、数据血缘。

### Skill执行日志如何追踪？

Skill执行追踪应把**一次任务、Skill版本、内部步骤、Tool调用和业务副作用**关联成统一Trace，同时区分可观测数据与合规审计证据。

1. **标识传播**：任务生成Trace ID，Skill、节点、模型、检索、Tool和审批创建Span；异步消息传播Trace Context，并关联租户、用户及各组件版本。
2. **结构化事件**：记录开始结束、参数摘要、状态、文档ID、Token与费用、授权、错误、重试、幂等键、外部操作ID和输出。写操作保留资源版本。
3. **隐私与可信**：正文按数据等级脱敏、加密或仅存哈希与引用，密钥不入日志。审计写入WORM或哈希链，调试日志限期分权保存。
4. **查询告警**：按Trace、Skill版本、主体、资源、错误和风险建立索引，构建调用图、P95延迟、成功率、成本和重复调用；越权、高危、异常批量和循环行为实时告警。
5. **回放限制**：用检查点和版本重建上下文，有副作用的Tool只模拟或经审批重放。

| 信号 | 用途 | 保留策略 |
|---|---|---|
| Trace | 链路与性能 | 采样，错误全量 |
| Log | 技术细节 | 短周期 |
| Metric | 聚合趋势 | 长周期 |
| Audit | 责任与合规 | 不可篡改、按法规 |

**相关知识点：** OpenTelemetry、Trace、Span、Context Propagation、结构化日志、WORM、幂等键、调用图、日志脱敏、审计证据。
<a id="tool-229"></a>
### Skill调用失败如何降级？

Skill失败降级应遵循**先分类、保状态、控副作用、再选择等价能力或人工路径**，降级结果必须明确标注，不能静默降低可信度。

1. **失败分类**：输入缺失、前置条件失败、模型错误、Tool瞬时故障、权限拒绝、结果校验失败和预算耗尽使用不同策略；返回结构化错误码、可恢复标志、检查点和已完成副作用。
2. **有界恢复**：瞬时且幂等的步骤指数退避重试；参数错误有限修正；模型不可用可切换经过同任务评测的备用模型；权限、安全和业务拒绝不得通过换Skill绕过。
3. **能力降级**：优先选择契约兼容的备用Skill、只读数据源、缓存或较小模型；无法完整完成时返回带证据的部分结果、排队稍后处理或人工接管。替代项必须重新鉴权并固定版本。
4. **状态与副作用**：通过幂等键和业务操作ID查询外部状态，部分完成时从检查点续作或Saga补偿；结果未知的非幂等写入暂停核对，禁止从头重跑。
5. **防止循环**：限制总重试、降级层数、步骤、时间和成本，记录失败指纹；同一根因未变化时不得在多个Skill间往返。

| 失败类型 | 降级路径 | 禁止事项 |
|---|---|---|
| 瞬时故障 | 重试/备用服务 | 无限重试 |
| 能力不足 | 备用Skill/部分结果 | 伪装完整成功 |
| 权限拒绝 | 终止/申请授权 | 绕过策略 |
| 状态未知 | 查询/人工核对 | 重复写入 |

线上监控降级率、降级后成功、用户接受、重复副作用和成本；长期高频降级应修复根因。

**相关知识点：** Fallback、错误分类、幂等、检查点、Saga、部分结果、人工接管、失败指纹、降级循环、透明标注。
