### CTX-002 · 长短期记忆是怎么设计的？短期记忆和长期记忆分别保存什么？（DeepSeek二面）

> 稳定 ID：`CTX-002`｜原题号：2

**短期记忆保存当前会话的执行现场，长期记忆保存跨会话仍成立的用户事实、偏好和经验；设计关键是分层存储、受控晋升与按需召回。**

1. 短期记忆属于任务工作区，包括目标、约束、近期对话、计划进度、工具结果、临时变量及待办。它写入Redis或Checkpoint，按会话和任务隔离，支持中断恢复；结束后按TTL清理，不能把全部历史持续追加到Prompt。

2. 长期记忆保存已确认的稳定偏好、身份事实、项目约束、重要事件和验证经验。写入前完成事实抽取、实体归一、去重、脱敏、价值评分与冲突检测，并记录来源、时间、置信度、版本、租户和有效期。**模型推断或一次性细节不能未经验证进入长期记忆**。

| 维度 | 短期记忆 | 长期记忆 |
| --- | --- | --- |
| 生命周期 | 单轮、会话或任务 | 跨会话、策略控制 |
| 核心内容 | 状态、计划、近期证据 | 事实、偏好、经验 |
| 典型存储 | Context、Redis、Checkpoint | 关系库、文档库、向量库 |

3. 推理前读取短期状态恢复现场，再按意图召回长期记忆，经权限、相关性、时效、置信度和冲突规则筛选后限量注入。任务结束时仅将有证据的高价值信息晋升到长期层；旧事实通过新版本失效，过期内容归档或删除。评估关注状态恢复成功率、有效使用率、错误记忆率、召回延迟和污染率。

**相关知识点：** Working Memory、Session State、Long-term Memory、Checkpoint、Memory Scoring、记忆晋升、冲突检测、TTL、版本管理。

### CTX-003 · Agent为什么必须设计记忆模块，短期对话记忆、长期持久记忆分别怎么落地，各自解决什么业务痛点（Agent中级）

> 稳定 ID：`CTX-003`｜原题号：3

**Agent必须配置记忆模块，因为模型调用天然无状态；记忆把分散交互转化为可恢复的任务状态和可复用的用户知识。**

1. 短期对话记忆保存目标、约束、指代实体、计划进度、工具回执、临时变量和待办，解决语义断裂、重复确认及任务中断。工程上以session_id维护结构化状态，Redis承担低延迟读写，结果写入Artifact Store，Prompt仅加载窗口、任务摘要与必要证据。

2. 长期持久记忆保存已确认的偏好、稳定事实、项目规范、重要事件及验证经验，解决个性化、重复任务加速和经验复用。关系库维护实体、版本、权限及有效期，向量库提供语义召回，对象存储保留原文。写入前执行抽取、去重、脱敏、可信度评分和冲突检测。

| 记忆层 | 直接解决的问题 | 主要治理风险 |
| --- | --- | --- |
| 短期记忆 | 会话连续、状态恢复 | 膨胀、过期状态 |
| 长期记忆 | 跨会话复用、个性化 | 污染、隐私、事实失效 |

3. 运行时先恢复短期状态，再按用户、意图和安全域检索长期记忆，经权限、时效、置信度及冲突校验后注入。任务结束后异步评估候选，只有可复用且有证据的信息才能晋升；新事实通过版本关系使旧记录失效，并执行衰减、归档或删除。**写入、召回、纠错与遗忘必须可解释、可撤销、可审计**。

**相关知识点：** Stateless Model、Session State、Working Memory、Long-term Memory、Artifact Store、Memory Scoring、记忆晋升、冲突检测、权限隔离。

### CTX-004 · 分层记忆完整体系：瞬时上下文记忆、短期会话记忆、长期持久记忆、知识库外部记忆四层设计；记忆自动压缩、过期清理、重要信息持久留存策略（Agent高级）

> 稳定 ID：`CTX-004`｜原题号：4

**四层记忆体系应按使用时点、归属主体和可信来源隔离，使即时推理、会话恢复、个体连续性与权威知识检索分别治理。**

1. 瞬时上下文服务单次调用，包含指令、当前问题、直接证据和工具Observation，结束即可释放。短期会话记忆保存目标、计划、变量、摘要、错误和Checkpoint，按会话、任务隔离并设置TTL，支持指代与中断恢复；两层内容均不能自动成为长期事实。

2. 长期持久记忆保存已确认的偏好、项目约束、事件和验证经验，以结构化记录、向量索引及引用跨会话复用。外部知识库保存制度、产品文档、代码和资料，由独立的采集、版本、权限及索引流程维护。**个体记忆表达“主体经历什么”，知识库表达“组织认定什么”，二者不能互相覆盖**。

| 层级 | 主要内容 | 生命周期 | 读取方式 |
| --- | --- | --- | --- |
| 瞬时上下文 | 指令与证据 | 单次调用 | 直接注入 |
| 短期会话 | 状态、计划、摘要 | 会话/任务 | 状态读取 |
| 长期持久 | 偏好、事件、经验 | 跨会话 | 检索 |
| 外部知识库 | 文档、规则、代码 | 版本控制 | RAG |

3. 压缩采用滚动摘要，保留约束、决策、待办、数字和原文引用，以摘要版本关联原消息。晋升长期层前按复用价值、稳定性、可信度和敏感度评分；短期数据按TTL清理，长期记录按时效和有效性衰减、归档或删除。重要事实追加版本，冲突记录保留来源。

**相关知识点：** Working Memory、Session Memory、Long-term Memory、External Knowledge、滚动摘要、记忆晋升、TTL、版本管理。

### CTX-005 · 为什么要把长期记忆分成静态长期记忆和动态长期记忆？（DeepSeek二面）

> 稳定 ID：`CTX-005`｜原题号：5

**静态与动态长期记忆必须分域治理，因为二者的数据来源、变化速度、可信边界和删除责任不同，混存会破坏权威性与个性化。**

1. 静态长期记忆包含制度、产品文档、代码规范、领域知识和已发布Skill，来源明确、更新频率低，由知识管理员或发布流程审核。它强调版本一致、权限控制、引用可追溯和批量索引，通常由对象存储保存原文，关系库维护元数据，倒排与向量索引提供检索。

2. 动态长期记忆来自用户交互和任务轨迹，包括偏好、历史事件、项目状态、任务经验和反思摘要。它变化频繁且可能出错，需要保存主体、时间、置信度、证据和有效期，并支持冲突追加、时间衰减及用户删除。**动态记忆只能描述主体状态，未经审核不能升级为组织知识**。

| 维度 | 静态长期记忆 | 动态长期记忆 |
| --- | --- | --- |
| 来源 | 审核发布的知识 | 交互与执行事件 |
| 更新方式 | 版本发布、索引切换 | 持续写入、冲突追加 |
| 主要目标 | 权威事实复用 | 连续性与个性化 |
| 核心风险 | 版本过期 | 错误累积、隐私泄漏 |

3. 召回时静态层按知识域、权限和版本过滤，动态层按用户、项目、时效及重要度过滤，再统一重排并标注来源。发生冲突时，制度和产品事实以有效静态版本为准，用户偏好以最新确认记录为准；无法裁决则保留双方证据并提示不确定性。两层必须使用不同写入门槛、保留期限、审计和删除流程。

**验证指标：** 上下文有效信息率、召回准确率、Token 占用、P95 组装延迟和陈旧信息率。

**相关知识点：** Static Memory、Dynamic Memory、知识库、Episodic Memory、版本发布、时间衰减、双路召回、冲突消解、数据权限。

### CTX-006 · 每一轮对话都触发长期记忆存储，会不会导致记忆膨胀？以后怎么处理？（DeepSeek二面）

> 稳定 ID：`CTX-006`｜原题号：6

**每轮对话都直接写入长期记忆一定会造成规模膨胀，并同时放大重复、过期、矛盾和错误信息，因此必须把事件留存与记忆晋升分开。**

1. 在线阶段仅把原始消息和执行轨迹追加到低成本事件日志，不同步写入长期检索库。任务完成、话题切换、用户明确表达稳定偏好、出现重要决策或达到周期阈值时，再触发Extractor生成候选记忆。候选必须满足可复用、较稳定、有来源、可归属且符合隐私策略；寒暄、临时情绪、一次性参数和模型猜测直接丢弃。

2. 写入前进行实体归一、内容哈希、语义去重和冲突检测。相同事实只补充证据、访问时间或置信度，发生变化时追加新版本并使旧值退出在线召回。**长期层保存结构化事实、事件摘要及证据引用，不复制完整聊天记录**；摘要必须能回溯原始事件，防止压缩后无法纠错。

3. 后台定期执行Memory Consolidation，把重复事件聚合为主题摘要或用户画像，保留代表性证据；低频但有审计价值的记录转入冷存，超过有效期、被用户否定或无合法用途的数据删除。系统按租户、用户和记忆类型设置容量及写入配额，并监控候选接受率、重复率、冲突率、有效召回率、错误记忆率和单位存储成本。治理目标不是单纯缩小体积，而是提高每条记忆对任务的净增益。

**相关知识点：** Event Log、写入门控、Memory Consolidation、语义去重、版本化记忆、TTL、冷存储、配额、用户删除权。

### CTX-007 · 大模型如何判断哪些长期记忆需要召回？如何避免召回太多导致上下文污染？（DeepSeek二面）

> 稳定 ID：`CTX-007`｜原题号：7

**长期记忆是否召回应由当前任务的信息缺口决定，召回多少则由相关性、可信度和Token预算共同限制，不能让模型无条件读取历史。**

1. Query Analyzer识别任务类型、用户、项目、实体、时间和记忆类别。若当前输入或实时数据足以回答，应跳过长期记忆；个性化、跨会话恢复、历史追溯或经验复用才触发检索。候选召回组合关键词、Embedding、实体关系和结构化过滤，并带入租户、用户、权限及有效状态。

2. Memory Reranker综合语义、实体一致性、时间衰减、重要度、来源可信度、使用效果和冲突程度评分。**向量相似度只能证明表达接近，不能证明记忆真实、有效或适用于当前任务**。重复记录聚类合并；矛盾版本保留来源和时间，优先用户确认或权威证据。

3. 注入阶段设置Token预算和最低分阈值，仅保留能改变决策的最小记忆集，以“事实—时间—来源—置信度”呈现，原文按引用展开。系统指令、当前目标和实时工具结果优先于历史记忆。线上记录候选数、注入数、有效使用率、错误引用率、上下文占比及任务增益，并用无记忆对照实验校准Top-K和阈值。

**相关知识点：** Query Analyzer、Memory Retrieval、元数据过滤、Memory Reranker、时间衰减、Token Budget、Context Pollution、冲突消解、消融实验。

### CTX-010 · 长短期记忆如何设计提取、压缩和冲突更新机制？（千问一面）

> 稳定 ID：`CTX-010`｜原题号：10

**长短期记忆治理应形成“事件提取—价值筛选—可追溯压缩—版本化冲突更新”的闭环，任何模型摘要都不能直接成为权威事实。**

1. 从消息、状态和工具轨迹提取目标、约束、实体、决策、待办、偏好及证据，先写短期状态。任务完成、话题切换、用户确认事实或达到容量阈值时，再生成长期候选。写入门控按稳定性、复用价值、可信度、敏感度和授权评分；寒暄、临时变量、模型猜测只留在日志层。

2. 压缩采用结构化事实与分层摘要并存：近期事件保留细节，旧事件聚合为主题、时间线或用户画像；摘要记录summary_id、source_id、时间范围、模型和Prompt版本，并关联原文。**数字、否定条件、截止时间、责任主体和未完成事项必须确定性保留与校验**，失败时回退原文。

3. 更新前区分同义重复、属性变化、并存事实和矛盾。重复项合并证据；偏好追加有效期；权威事实按来源和版本处理；无法裁决的矛盾并存并标记conflict。变化记录created_at、supersedes、操作者和原因，召回选择当前有效版本，并允许用户纠正、撤销和查看历史。评估提取准确率、压缩保真度、重复率、冲突误判率和错误记忆率。

**相关知识点：** Memory Extraction、写入门控、Memory Compression、证据溯源、双时态版本、语义去重、冲突消解、用户纠正、审计日志。

### CTX-013 · 多轮对话优化：多轮对话不断累积历史消息，上下文过长、Token消耗过高该怎么优化（Agent初级）

> 稳定 ID：`CTX-013`｜原题号：13

**多轮对话不能持续回传全部消息，应把原始历史外置存储，并将当前窗口、结构化状态和滚动摘要动态组合成最小充分上下文。**

1. 消息分别保存原文日志和会话状态；Prompt只保留近期对话、当前目标、硬约束、已确认事实、待办及工具错误。达到轮数、Token或话题切换阈值时，把旧消息压缩为结构化摘要，包含目标、决策、实体、时间、待办和证据引用。摘要通过summary_version关联原消息，数字、否定和用户纠正需校验。

2. **摘要不是永久替代原文，而是可回溯的索引层**。当用户追问细节、出现冲突或摘要置信度不足时，应按message_id重新加载相关原文；不同话题分支分别摘要，避免把无关内容混为一段。长期稳定偏好可经过写入门控进入Memory，一次性参数继续留在会话状态，防止长期库膨胀。

3. Token预算先预留输出和工具调用，再按System规则、当前问题、状态、近期窗口、摘要、Memory分配。删除寒暄、完整工具日志和低相关历史，稳定前缀启用Prompt Cache。线上统计输入/输出Token、压缩率、原文回退率、保真度、P95和成功率；以单位成功会话成本评估，不能只追求Token下降。

**相关知识点：** Sliding Window、Rolling Summary、Session State、Token Budget、Prompt Cache、摘要版本、原文回退、Memory写入门控。

### CTX-018 · 为什么要区分短期 Memory 和长期 Memory？

> 稳定 ID：`CTX-018`｜原题号：18

**短期Memory与长期Memory必须区分，因为当前任务状态需要低延迟、强一致和及时清理，而跨会话知识需要筛选、持久化及按需检索。**

1. 短期Memory保存目标、计划、近期消息、临时变量、工具结果、错误和待办，生命周期是单轮、会话或任务。它按会话和任务隔离，存于上下文、Redis或Checkpoint，要求顺序一致；任务结束或TTL到期后清理。一次性细节长期保存会产生膨胀、误召回和过期。

2. 长期Memory保存已确认的偏好、身份事实、项目约束、事件和验证经验，通过关系库、事件库及向量索引持久化。写入前需抽取、去重、脱敏、价值评分、冲突检查和授权。**短期信息不能自动晋升为长期事实，长期信息也不能全部直接注入当前Prompt**。

| 维度 | 短期Memory | 长期Memory |
| --- | --- | --- |
| 目标 | 保持当前任务连续 | 跨会话复用 |
| 生命周期 | 单轮、会话、任务 | 策略控制的长期 |
| 读取 | 直接状态、近期窗口 | 过滤、检索、重排 |

3. 运行时先恢复短期状态，再按意图召回少量长期候选，经权限、相关性、时效和冲突校验后注入。任务结束时异步评估晋升内容；旧事实由新版本失效，低价值内容衰减、归档或删除。监控状态恢复率、长期记忆使用率、错误记忆率和污染率。

**相关知识点：** Working Memory、Session State、Long-term Memory、Checkpoint、Memory Scoring、记忆晋升、时间衰减、版本管理。

### CTX-019 · Memory 如何更新？

> 稳定 ID：`CTX-019`｜原题号：19

**Memory更新应采用“候选事实抽取—同一实体匹配—冲突分类—追加版本—索引刷新”的流程，不能直接覆盖原记录。**

1. 新事件抽取subject、predicate、value、source、valid_time、confidence和scope，并按用户、项目及实体ID匹配旧记忆。重复事实只增加证据；属性变化追加新值；可并存事件保留多条；真正矛盾进入冲突队列。模型推断、低置信信息和一次性参数不更新长期层。

2. **长期记忆应使用追加版本而非原地静默覆盖**。新记录保存memory_id、version、valid_time、supersedes和reason，旧记录失效但保留审计；用户明确纠正优先于模型抽取，组织规则不能被个体偏好覆盖。敏感信息更新时重新执行授权、脱敏和期限检查。

3. 元数据提交后，通过Outbox异步更新向量与关键词索引，以memory_id和version幂等；失败进入重试与DLQ，查询只读有效版本。删除采用墓碑并清理索引和缓存。定期执行语义去重、时间衰减和Memory Consolidation。监控更新成功率、重复率、冲突率、旧版本误召回率、索引延迟和纠错率，并支持回滚。

**相关知识点：** Memory Update、Append-only Version、Valid Time、Supersedes、Outbox、幂等索引、冲突分类、墓碑删除、Memory Consolidation。

### CTX-020 · Memory 如何压缩？

> 稳定 ID：`CTX-020`｜原题号：20

**Memory压缩应减少重复和低价值细节，同时保留可执行约束、关键事实、时间关系与原文证据，并保证摘要可回溯、可更新。**

1. 压缩前先按用户、项目、实体、主题和时间窗口聚类，删除完全重复项，合并同义事实的证据与访问统计。近期事件保留细粒度，较旧事件按主题或时间线生成Summary Memory；稳定偏好和实体属性转成结构化字段，原始对话、工具轨迹继续存放在低成本日志层，不与摘要混存。

2. **压缩后的摘要必须记录summary_id、source_memory_ids、时间范围、模型、Prompt版本和置信度**。数字、否定、截止时间、责任主体、未完成事项和用户纠正采用规则校验；冲突事实不能合并成单一值，应保留版本、来源和冲突标记。摘要低置信或用户追问细节时，按引用回退原始记忆。

3. 触发条件可组合Token或条目阈值、会话结束、长期未访问和定期维护；压缩后先写新摘要，再原子更新引用，旧记录转冷存或按保留策略删除。多级摘要采用叶子事件—主题摘要—用户或项目画像，但每层限制摘要嵌套深度，避免反复生成造成语义漂移。评测包含压缩率、事实保留率、数值准确率、冲突保留率、原文回退率和任务成功率。

**相关知识点：** Memory Compression、Summary Memory、语义去重、分层摘要、证据溯源、冷存储、语义漂移、事实保留率、原文回退。

### CTX-021 · Memory 如何检索？

> 稳定 ID：`CTX-021`｜原题号：21

**Memory检索应先判断当前任务是否需要历史，再通过权限过滤、多路召回、记忆重排和Token预算选出最小有效记忆集。**

1. Query Analyzer提取用户、项目、实体、时间和记忆类型；若当前输入或实时API足以回答，应跳过Memory。检索前加入租户、用户、scope、ACL、valid_time和active_version过滤。候选阶段并行使用向量、关键词、实体属性和事件时间线，覆盖语义改写、精确事实及关系查询。

2. Memory Reranker综合语义相关性、实体一致性、时效、重要度、来源可信度、历史使用效果和冲突状态。**向量相似度只表示文本接近，不能证明记忆真实、有效或属于当前用户**。重复候选按memory_id和语义聚类合并，被替代版本退出默认结果，矛盾项保留来源并降低自动采用置信度。

3. 按阈值和Token预算选择Top-N，以“事实、时间、来源、置信度、引用”注入；系统规则、当前状态和实时工具事实高于历史记忆。低置信时不注入或请求确认，原文按引用展开。离线评估Recall@K、MRR、冲突检出率和无关召回率，线上观察有效使用率、错误引用率、任务增益、P95及上下文占比，并用无Memory实验校准阈值。

**相关知识点：** Query Analyzer、Memory Retrieval、元数据过滤、混合召回、Memory Reranker、时间衰减、Top-N、上下文污染、消融实验。

### CTX-023 · 反思结果如何存储到长期记忆？

> 稳定 ID：`CTX-023`｜原题号：23

**反思结果应先转化为可验证、可检索、可更新的结构化经验，再经过质量门写入长期记忆，而不是保存整段模型自述。**

1. 反思模块从轨迹中抽取“适用条件—采取动作—结果—失败原因—改进策略”，同时保存任务类型、工具版本、输入特征、证据引用、评价分数和时间。经验必须与原始Trace关联，便于复核；模型未能由执行结果支持的推断标为候选，不得直接成为事实。存储可区分情景记忆与语义记忆：前者保留一次任务案例，后者沉淀跨案例稳定规律。

2. 写入前执行事实一致性、重复、权限、敏感信息和毒性检查，并以人工审核、单元测试或多次成功轨迹确认。**长期记忆保存的是经过验证的经验单元，不是不可审计的思维链**。每条记录携带置信度、成功次数、失败次数、适用范围、版本、失效时间和状态；低置信内容进入隔离区，高风险策略必须人工批准。

3. 召回时先按租户与权限过滤，再结合语义相似度、任务标签、时效、成功率和上下文条件排序，避免把局部经验误用于其他场景。新反馈采用追加版本或事件溯源更新，不原地覆盖；出现反例时降低置信度、缩小适用域或撤销。周期性合并近义经验、淘汰过期规则，并用命中后成功率、负迁移率和人工纠错率评估记忆价值。

**相关知识点：** Reflection、Episodic Memory、Semantic Memory、经验单元、Trace、质量门、置信度、事件溯源、记忆衰减、负迁移。

### CTX-025 · 如何避免错误经验被写入长期记忆？

> 稳定 ID：`CTX-025`｜原题号：25

**避免错误经验进入长期记忆的关键是将“生成候选”和“正式写入”彻底分离，以证据、验证和生命周期治理建立多级质量门。**

1. 反思输出默认进入候选区，不直接进入可召回索引。候选必须关联原始输入、工具结果、执行Trace、评价信号和责任主体，并区分用户明确事实、外部证据、模型推断与策略建议。缺少来源、仅凭一次成功、执行失败后自我解释或包含不可核验因果的内容，应拒绝写入或保持低置信状态。

2. 写入管线依次执行模式校验、事实核对、权限与敏感信息检查、重复检测、冲突检测和独立评测。可用规则引擎验证确定性约束，用测试或沙箱复现操作经验，用权威知识源核验事实；高影响经验采用人工复核或双模型交叉评审。**模型自洽不等于事实正确，只有可追溯证据和外部结果才能提高可信度。**

3. 正式记录携带置信度、适用条件、版本、有效期、验证方法和撤销标记；召回时同时考虑任务匹配度与可信等级，禁止低置信经验驱动高风险动作。新证据与旧经验冲突时不覆盖原文，而是追加版本、降低权重或隔离，并触发复核。持续监控命中后失败率、用户纠错率和负迁移率，超过阈值自动降级、撤回并回放受影响任务。

**相关知识点：** 候选记忆、Provenance、Trace、置信度、事实核验、冲突检测、沙箱复现、交叉评审、版本化、记忆撤销、负迁移。

### CTX-027 · 短期记忆和上下文窗口是什么关系？

> 稳定 ID：`CTX-027`｜原题号：27

**短期记忆是Agent维护的任务状态，上下文窗口是模型单次推理接收的Token容量；前者是逻辑层，后者是计算边界。**

1. 短期记忆包含目标、计划、已完成动作、变量、工具结果、用户确认事实与未决事项，通常存放在会话状态、缓存或数据库中，可跨越多次模型调用。上下文窗口只承载某次调用注入的System、历史、检索证据和输出预算；窗口关闭后，模型不会自动保留其中信息。

| 维度 | 短期记忆 | 上下文窗口 |
| --- | --- | --- |
| 本质 | 外部维护的任务状态 | 模型输入容量 |
| 生命周期 | 一次任务或会话 | 单次推理 |
| 超限处理 | 摘要、分层、持久化 | 截断或减少输入 |

2. Context Builder从短期记忆中选择与当前步骤有关的部分注入窗口，因此二者不是包含关系，也不能等同。**扩大上下文窗口只提高可注入上限，不能替代状态建模、检索和压缩**；把全部状态反复塞入模型仍会产生注意力稀释、冲突、延迟及成本问题。

3. 工程实现应结构化保存关键状态及来源、时间、版本和有效性；每轮按硬约束、当前步骤、直接证据、最近交互排序组装。旧轨迹可摘要，必要时回查原文；工具大结果存外部对象，仅注入相关片段。评测关注状态恢复准确率、约束遗漏率、Token消耗与任务成功率。

**相关知识点：** Short-term Memory、Context Window、Session State、Context Builder、Token Budget、状态持久化、分层摘要、按需检索、Lost in the Middle。

### CTX-028 · 长期记忆为什么要使用向量数据库？

> 稳定 ID：`CTX-028`｜原题号：28

**向量数据库把自然语言经验映射为语义向量，使Agent能按含义而非相同关键词召回长期记忆。**

1. 用户表达与经验记录常有同义改写、缩写及表述差异，倒排检索容易漏掉关键词不重合但语义相近的内容。Embedding将查询与记忆编码到同一空间，向量库通过HNSW、IVF等ANN索引取得Top-K，并支持元数据过滤、分区、增量写入和删除。

| 方案 | 优势 | 局限 |
| --- | --- | --- |
| 关键词检索 | 精确、可解释 | 同义表达召回弱 |
| 向量检索 | 语义召回强 | 可能命中表面相似内容 |
| 关系数据库 | 过滤与事务可靠 | 不擅长自由文本语义匹配 |

2. **向量数据库只是检索索引，不应成为事实、权限和事务的唯一载体**。原文、来源、版本、置信度、租户、ACL、有效期及状态仍需结构化保存；检索先做权限与时间过滤，再融合BM25、向量相似度、重要性、近期性和成功率，必要时用Reranker精排，避免不适用的经验进入Prompt。

3. 选型取决于规模和查询模式：少量结构化偏好用关系库即可，编号查询优先关键词或SQL。上线前评估Recall@K、命中后成功率、误召回率、P95、成本和租户隔离；Embedding或切分策略升级时建立新索引并灰度切换，避免向量空间变化破坏召回。

**相关知识点：** Embedding、Vector Database、ANN、HNSW、IVF、Metadata Filter、Hybrid Search、Reranker、Recall@K、索引版本。

### CTX-029 · Agent为什么需要分层记忆体系？

> 稳定 ID：`CTX-029`｜原题号：29

**Agent需要分层记忆，因为任务状态、会话信息和长期知识的时效、可信度及访问成本不同，统一存储会造成污染与低效召回。**

1. 工作记忆承载当前变量、工具结果和待办，随任务结束清理；短期记忆保存会话目标、约束和摘要，用于跨轮恢复；长期记忆保存验证过的事实、知识和经验，需要检索、版本及权限治理。分层后，Agent只向Prompt注入当前所需信息，降低Token成本和注意力稀释。

| 层级 | 典型内容 | 生命周期 |
| --- | --- | --- |
| 工作记忆 | 当前变量、执行状态 | 单步或单任务 |
| 短期记忆 | 会话摘要、未决事项 | 一次会话 |
| 长期记忆 | 稳定事实、验证经验 | 跨会话 |

2. **分层的核心不是选择数据库，而是建立不同的写入门槛、召回策略和淘汰规则**。瞬时结果不应自动沉淀；会话摘要需保留来源；长期记忆必须经过事实核验、去重、敏感信息和权限检查。召回时先读取工作状态，再恢复短期内容，最后以ACL、时效、置信度和相关度检索长期记忆。

3. 更新采用稳定memory_id和追加版本，冲突事实并存并标注有效区间，过期内容降权或删除。系统评估状态恢复准确率、有效命中率、错误记忆率、跨租户泄漏、Token节省和任务成功率；若某层无法改善指标，应简化架构，避免无效复杂度。

**相关知识点：** Working Memory、Short-term Memory、Long-term Memory、记忆巩固、Memory Scoring、时间衰减、版本管理、ACL、墓碑删除。

### CTX-030 · 工作记忆、短期记忆和长期记忆有什么区别？

> 稳定 ID：`CTX-030`｜原题号：30

**三类记忆分别服务于单步推理、会话连续性和跨会话复用，差异在生命周期、内容、写入门槛与召回方式。**

| 类型 | 典型内容 | 生命周期 | 获取方式 |
| --- | --- | --- | --- |
| 工作记忆 | 当前变量、步骤、工具结果 | 单步或单任务 | 直接读取 |
| 短期记忆 | 会话目标、约束、阶段摘要 | 一次会话 | 状态恢复 |
| 长期记忆 | 稳定事实、偏好、验证经验 | 跨会话 | 检索召回 |

1. 工作记忆类似执行白板，保存当前计划位置、变量、文件引用、工具错误和待办，追求低延迟，不宜长期保留。短期记忆对多轮轨迹进行提炼，使下一轮恢复任务目标、用户确认事项和未完成步骤；它可跨模型调用，通常随会话结束归档或清理。

2. 长期记忆面向未来任务，只接收有持续价值且经核验的事实或经验，保存来源、置信度、版本、有效期、租户和ACL，并通过关键词、向量或图关系召回。**短期记忆强调连续性，长期记忆强调可复用性；聊天历史久远不会自动成为长期记忆。**

3. 三层采用受控流转：工作结果先形成会话摘要，重复成功且可验证的候选再巩固；反例出现时降低置信度或撤销。注入Prompt时优先工作状态，其次恢复短期信息，最后检索长期证据。评测关注步骤状态正确率、会话恢复准确率、长期有效命中率、错误记忆率和Token成本。

**相关知识点：** Working Memory、Short-term Memory、Long-term Memory、Session State、Episodic Memory、Semantic Memory、记忆巩固、Memory Retrieval、ACL。

### CTX-031 · Memory Service应该独立部署吗？

> 稳定 ID：`CTX-031`｜原题号：31

**Memory Service不应默认独立部署；当记忆被多个Agent复用、需要独立扩缩容或统一安全治理时，服务化才具有明确收益。**

| 形态 | 适用场景 | 主要代价 |
| --- | --- | --- |
| 进程内模块 | 单Agent、低流量、快速迭代 | 难跨应用复用 |
| 独立服务 | 多Agent、多租户、规模化检索 | 网络与运维复杂度 |

1. 独立部署可统一写入、召回、去重、版本、TTL、ACL和审计，避免各Agent形成不一致的记忆格式；读写压力也可独立扩展，并隔离Embedding、索引构建等重负载任务。它适合需要跨渠道共享用户偏好、集中删除个人数据、执行租户隔离或设定服务级目标的系统。

2. 服务化会增加一次或多次网络调用，引入延迟、序列化、认证、容量规划、故障传播和数据一致性问题。**如果只有单体应用、数据量小且没有跨Agent复用，清晰的Memory模块通常比微服务更合理**；先定义稳定接口和存储抽象，达到流量、团队或治理阈值后再拆分，可降低过早分布式化成本。

3. 独立服务需提供幂等写入、版本化更新、批量检索、权限过滤和可解释来源；读路径设置超时、熔断、缓存及“无记忆继续执行”的降级，写路径采用队列和重试但不能重复沉淀。监控可用性、P95、数据新鲜度、有效命中率、错误记忆率、跨租户访问和单位成本，并通过容量测试与故障演练验证拆分价值。

**历史别名：** `CTX-148`。

**相关知识点：** Memory Service、模块化单体、微服务、ACL、多租户、幂等写入、最终一致性、熔断降级、数据新鲜度、SLO。

### CTX-032 · 长期记忆如何存储、召回和更新？

> 稳定 ID：`CTX-032`｜原题号：32

**长期记忆应采用“原始记录与索引分离、混合召回、版本化更新”的闭环，确保内容可追溯、结果可解释、错误可撤销。**

1. 存储时先把事实、偏好、案例或经验转换为结构化记录，包含memory_id、主体、内容、类型、来源、证据、置信度、租户、ACL、创建时间、有效期和版本。原文与审计事件放事务库或对象存储，Embedding和关键词字段作为派生索引；写入前执行去重、冲突、敏感信息和价值检查，模型推断进入候选区。

2. 召回先按用户、租户、权限、状态和有效期硬过滤，再结合关键词、向量相似度、实体关系、近期性、重要度及成功率生成候选，由Reranker选出最小证据集。**语义相似度只表示内容接近，不代表事实正确或经验适用**；注入Prompt时必须携带来源、时间和置信度，并限制低可信记忆影响高风险决策。

3. 更新不应原地覆盖，而应追加新版本并标记supersedes关系；用户纠错、执行反例或来源变更触发降权、缩小适用范围、过期或墓碑删除。索引通过event_id幂等更新，失败进入重试与对账；Embedding升级使用影子索引和原子切换。系统评估有效命中率、命中后成功率、错误记忆率、更新延迟、删除完整性和跨租户泄漏。

**历史别名：** `ARC-037`。

**相关知识点：** Memory Schema、Provenance、Hybrid Retrieval、Reranker、Memory Scoring、Supersedes、幂等更新、墓碑删除、影子索引、记忆衰减。

### CTX-033 · 记忆层如何避免信息污染？

> 稳定 ID：`CTX-033`｜原题号：33

**记忆层防污染必须同时控制写入来源、事实状态、命名空间、召回权重和撤销机制，不能让一次对话或模型输出直接成为可信记忆。**

1. 写入入口按用户明确陈述、权威外部证据、工具结果、模型推断和反思经验分类，记录来源、证据、主体、时间、租户与权限。用户事实和系统事实分域，外部网页、模型回答及执行失败后的归因先进入候选区；完成格式、去重、事实、敏感信息和Prompt Injection检查后，才允许发布到可召回索引。

2. **相似度高不代表可信，召回排序必须把来源权威性、验证状态、时效和适用范围作为独立信号**。检索前以服务端身份执行tenant_id、ACL、状态和有效期硬过滤，向量库、关键词索引、缓存与原始存储保持同一授权语义；不同用户、环境和任务域采用命名空间隔离，防止跨租户或测试数据进入生产上下文。

3. 更新采用追加版本和supersedes关系，冲突内容不静默覆盖；出现用户纠错、反例或来源撤回时降低置信度、隔离或墓碑删除，并同步清理缓存和派生索引。保留完整读写审计，定期抽样复核高命中记忆，监控错误写入率、冲突率、负迁移率、过期命中、跨租户命中和删除完整性；异常批次可按来源或版本整体回滚。

**历史别名：** `ARC-082`。

**相关知识点：** Memory Poisoning、候选记忆、Provenance、Namespace、ACL、Prompt Injection、置信度、Supersedes、墓碑删除、负迁移、审计追踪。

### CTX-034 · 如何设计记忆检索机制？

> 稳定 ID：`CTX-034`｜原题号：34

**记忆检索应采用“触发判断—权限过滤—多路召回—可信重排—受控注入”的链路，只返回当前决策所需的少量有效记忆。**

1. 首先由检索路由器判断当前是否需要历史信息，并从请求中提取用户、任务类型、实体、时间、目标和约束，生成语义查询与关键词查询。简单计算、已有充分上下文或高时效外部事实可以跳过记忆检索，避免无关经验干扰；涉及用户偏好、任务延续、决策或重复故障时再触发记忆域。

2. 服务端先以tenant_id、user_id、ACL、状态和有效期硬过滤，再并行执行BM25、向量近邻、实体关系和最近事件召回。候选可用RRF融合，再由Reranker综合语义相关度、来源权威性、置信度、时效、重要度、历史成功率与适用条件排序。**相关性只决定是否相近，可信度和适用性决定能否用于行动。**

3. 精排后按实体、事件和来源去重，识别冲突版本，压缩为带memory_id、来源、时间及置信度的证据块；低于阈值时返回“无可靠记忆”，不得强行填充。Top-N由Token预算和分数断层确定。离线使用时间切分评测Recall@K、MRR和冲突识别率，线上观察有效使用率、命中后成功率、负迁移率、P95及成本，并记录采用或忽略原因。

**相关知识点：** Retrieval Router、Query Construction、Hybrid Retrieval、RRF、Memory Scoring、Reranker、时间衰减、冲突检测、动态Top-K、负迁移。

### CTX-035 · 什么信息应该进入长期记忆？

> 稳定 ID：`CTX-035`｜原题号：35

**应进入长期记忆的是未来任务可复用、经过验证、边界明确且允许保存的信息，而不是对话中出现过的全部内容。**

1. 适合沉淀的内容包括用户明确确认且相对稳定的偏好、身份相关非敏感事实、长期目标与固定约束；经权威来源验证的领域事实、术语和组织规则；多次任务中复现的有效经验、失败模式和决策依据；以及跨会话仍需恢复的项目里程碑。每项内容都要回答“未来何种任务会使用、依据是什么、何时失效”。

2. 写入决策可按持久价值、复用频率、可信度、独特性和保存风险评分。**高相关不等于值得长期保存，只有收益大于隐私、污染和维护成本的内容才应晋级**。单次工具输出、临时状态和未经证实的推断先留在工作或短期记忆；高风险个人信息即使有用，也必须满足最小化、明确授权和保留期限要求。

3. 长期记录应结构化保存主体、类型、内容、来源、证据、置信度、适用范围、租户、ACL、版本、有效期和删除依据，并关联原始事件。事实、偏好、情景案例与策略经验分域管理，避免召回时混淆。上线后以有效命中率、命中后成功率、用户纠错率、负迁移率和删除请求完成率检验价值，长期未使用或反复造成错误的内容应降权、复核或淘汰。

**相关知识点：** Long-term Memory、记忆价值评分、用户偏好、Semantic Memory、Episodic Memory、Provenance、数据最小化、有效期、负迁移。

### CTX-036 · 什么信息不应该被长期保存？

> 稳定 ID：`CTX-036`｜原题号：36

**不具备持续价值、无法验证、超出授权或一旦泄露会造成高风险的信息，不应进入长期记忆。**

1. 明文密码、访问令牌、私钥、验证码、支付凭据等认证秘密必须禁止保存；身份证件、精确位置、健康、财务、生物特征及其他敏感个人信息，除非业务必需、取得明确授权并满足法规和保留期限，否则也不应沉淀。跨租户数据、超出用途的数据和用户已要求删除的内容不得以摘要、向量、缓存或备份副本继续存在。

2. 临时变量、中间推理、调试日志、一次性工具结果、已完成任务的过程噪声和短期会话状态，应在工作记忆或受限日志中按期清理。模型猜测、未经核验的反思、来源不明内容、恶意指令及失败后的主观归因不能作为事实写入。**记忆系统应保存可审计结果和证据，不应保存不可验证的思维链。**

3. 写入网关应依据数据分类、用途、授权、可信度、复用价值和有效期执行策略，敏感模式检测只能作为辅助，不能替代字段白名单与权限控制。被拒内容记录原因但不复制原文；允许内容采用最小化、脱敏、加密和TTL。删除时同步处理主存、向量索引、搜索索引、缓存与可控备份，并审计错误写入率、敏感数据检出率和删除完整性。

**相关知识点：** 数据最小化、敏感个人信息、Secrets Management、Purpose Limitation、TTL、脱敏、Right to Erasure、Prompt Injection、删除证明。

### CTX-037 · Skill和Memory有什么区别？

> 稳定 ID：`CTX-037`｜原题号：37

**Skill定义“任务怎样完成”，Memory记录“发生过什么或已知什么”；前者是方法资产，后者是有主体和时间的事实或经历。**

| 维度 | Skill | Memory |
| --- | --- | --- |
| 内容 | 步骤、工具、约束、校验 | 事实、偏好、事件、经验 |
| 适用范围 | 同类任务复用 | 特定主体或情境 |
| 更新方式 | 测试后版本发布 | 追加、纠错、衰减或删除 |
| 触发方式 | 按任务能力匹配 | 按相关性与权限召回 |

1. Skill包含适用条件、输入输出契约、步骤、工具依赖、异常分支、完成标准和回滚方式，经测试或沙箱验证发布。“数据库迁移检查流程”属于Skill。它追求可复现与跨用户复用，不应隐含用户权限、令牌或个体事实。

2. Memory包含用户偏好、项目状态、决策、案例及验证事实，保存来源、主体、时间、置信度、ACL和有效期。例如“用户要求报告使用中文”属于Memory。**重复成功的Memory可以成为Skill的证据，但必须经过抽象、去个性化和独立验证，不能直接晋级。**

3. 运行时先按任务类型选择Skill，再检索与主体和情境有关的Memory，用记忆参数化流程。两者应分库或分命名空间，采用不同审核、版本和删除策略；Skill变更看回归成功率与副作用，Memory治理看有效命中率、错误记忆率、隐私合规与负迁移。

**相关知识点：** Skill、Memory、输入输出契约、任务路由、Episodic Memory、Semantic Memory、经验抽象、版本发布、Memory Retrieval、负迁移。

### CTX-038 · Agent如何自动沉淀长期记忆？

> 稳定 ID：`CTX-038`｜原题号：38

**Agent自动沉淀长期记忆应采用候选生成、价值评分、证据验证、受控发布和反馈淘汰的异步管线，自动化不代表无审核写入。**

1. 在任务完成、用户确认、错误纠正或阶段结束等事件触发抽取器，从对话和执行Trace中识别稳定事实、偏好、项目状态、决策依据及可复用经验，并生成结构化候选。候选保留原始证据、主体、任务类型、时间和工具结果；模型的因果解释、未执行计划和中间推理不得直接作为事实。

3. 通过质量门的记录以memory_id和版本幂等发布，原文、元数据、关键词及向量索引分别存储；高风险或冲突内容进入人工队列。召回后的采用、忽略、任务成功和用户纠错作为反馈，更新置信度与适用范围。定期合并近义项、降权长期未用项、撤销反复出错项，并监控候选接受率、错误写入率、有效命中率、负迁移率和删除完整性。

**相关知识点：** Memory Consolidation、Event Trigger、Trace、候选记忆、价值评分、质量门、实体归一、幂等写入、反馈学习、记忆衰减。

### CTX-039 · 记忆压缩（Memory Compression）如何实现？

> 稳定 ID：`CTX-039`｜原题号：39

**记忆压缩应在保留事实、约束、时间关系和证据引用的前提下降低冗余，原始记录必须可回溯，摘要不能成为不可逆的唯一事实源。**

| 方法 | 适用对象 | 风险 |
| --- | --- | --- |
| 去重合并 | 重复事件、近义记录 | 错并不同条件 |
| 抽取式压缩 | 事实、数字、引用 | 上下文关系丢失 |
| 分层摘要 | 长会话、任务轨迹 | 摘要漂移 |

1. 先按memory_id、内容哈希、实体、时间窗口和语义相似度发现重复项，再依据来源与适用条件决定合并；冲突记录不能去重，应保留版本和supersedes关系。会话轨迹可抽取目标、硬约束、已完成动作、关键结果、错误及未决事项，工具大结果仅保存对象引用、校验值和必要片段。

2. 对长历史采用事件摘要、阶段摘要和任务摘要三级结构，每级保存覆盖的原始ID、时间范围、摘要模型与版本。**数字、否定、权限、截止时间、异常和用户确认内容必须作为不可丢失槽位单独校验**；生成式摘要后用规则比对关键字段，并以问答或事实一致性测试检查压缩前后语义。

3. 召回先检索摘要，证据不足或风险较高时沿引用展开到原始事件，实现渐进式读取。压缩任务应异步、幂等并版本化，失败不覆盖旧摘要；原文依据合规保留策略归档或删除。评测使用压缩率、事实保留率、约束遗漏率、引用可达率、任务成功率和Token节省，不能只追求文本变短。

**相关知识点：** Memory Compression、去重、抽取式压缩、分层摘要、Progressive Retrieval、Supersedes、摘要漂移、事实一致性、压缩率。

### CTX-040 · 如何设计遗忘机制（Forgetting Mechanism）？

> 稳定 ID：`CTX-040`｜原题号：40

**遗忘机制应先降低低价值记忆的召回概率，再按保留策略归档或删除，使容量受控，同时保证重要事实可追溯、法定删除可证明。**

1. 每条记忆维护创建时间、最后访问时间、命中次数、使用后成功率、置信度、重要度、有效期和合规保留级别。衰减分数可综合时间间隔、使用频率、任务价值与反例数量；稳定用户偏好、法律凭证和项目关键决策设置保护等级，临时状态、重复事件及低可信推断采用较快衰减，避免统一TTL误删高价值内容。

2. 处置分为降权、压缩、冷归档和物理删除：低分记录先退出默认召回，近义事件合并为带引用的摘要，审计价值存在但使用稀少的内容进入低成本存储，达到期限或响应用户删除请求时执行墓碑和异步清理。**遗忘不是简单删除原文，而是使记忆在召回、索引、缓存和备份层同步退出使用。**

3. 清理任务按tenant和时间分片，使用event_id幂等执行，并对事务库、向量索引、倒排索引、缓存及对象存储进行对账；删除失败进入重试和告警。上线前回放历史任务，验证遗忘后成功率与关键记忆召回不下降；持续监控容量增长率、低价值命中率、误删率、删除延迟、恢复需求和删除完整性，并保留策略版本及审计记录。

**相关知识点：** Forgetting Curve、Memory Decay、TTL、重要度评分、冷归档、记忆压缩、墓碑删除、Right to Erasure、删除证明、数据保留策略。

### CTX-041 · Agent 的短期记忆和长期记忆如何协同工作？

> 稳定 ID：`CTX-041`｜原题号：41

**短期记忆负责维持当前会话状态，长期记忆提供跨会话事实与经验；两者通过按需召回、受控晋级和结果反馈形成双向协同。**

1. 任务开始时先加载当前请求与会话状态，再根据用户、项目、实体和任务类型检索少量长期记忆；召回结果携带来源、时间、置信度及适用范围，被写入短期状态的“参考证据”区域，不能覆盖系统指令或当前用户确认。执行过程中，计划位置、工具结果、临时变量和未决事项只在短期层更新，避免频繁污染长期库。

2. 会话结束或出现用户确认、任务成功、错误纠正等事件时，从短期轨迹提取候选事实与经验，执行去重、冲突、权限、敏感信息和价值检查。**短期信息只有具备持续价值并获得证据支持，才能经过记忆巩固进入长期层**；一次性状态、失败计划和模型推断随会话过期，不因被多次复述而提高可信度。

3. 下一次召回后记录该记忆是否被采用、是否改善结果以及是否被用户纠正，用于调整置信度、重要度和适用范围；反例触发降权或撤销。工程上以session_id、task_id和memory_id建立引用，原始会话与长期摘要分离保存。评测关注会话恢复准确率、长期有效命中率、错误晋级率、负迁移率、Token成本和任务成功率。

**相关知识点：** Short-term Memory、Long-term Memory、Memory Consolidation、Session State、按需召回、候选记忆、置信度更新、反馈闭环、负迁移。

### CTX-042 · Episodic Memory 和 Semantic Memory 有什么区别？

> 稳定 ID：`CTX-042`｜原题号：42

**Episodic Memory记录任务经历，Semantic Memory保存脱离单次事件仍成立的事实和规律；前者回答“发生过什么”，后者回答“知道什么”。**

| 维度 | Episodic Memory | Semantic Memory |
| --- | --- | --- |
| 内容 | 任务轨迹、动作、结果 | 事实、概念、稳定规律 |
| 上下文 | 强依赖时间与场景 | 可跨场景复用 |
| 召回 | 按相似案例和时间 | 按实体、关系和语义 |

1. 情景记忆保留任务目标、动作、结果、反馈和时间，例如某次部署因配置缺失而回滚。它适合案例类比、复盘和恢复任务，但经验可能只在当时环境成立。语义记忆保存项目约束、用户偏好、实体关系或从多次案例归纳的稳定模式，适合支持判断。

2. **多个相似情景可提供语义归纳证据，但不能由单个成功案例推出普遍规则**。归纳时去除偶然参数，保留适用条件、反例和证据ID，并用独立任务验证；新事实与旧规则冲突时追加版本或降低置信度，不能修改历史事件。语义记忆应能追溯其情景来源。

3. 检索时先用语义记忆提供规则，再用相似情景补充细节；两类内容必须标记类型，避免把案例当规范。情景层评测案例命中率、时间正确率和复现价值，语义层评测事实准确率、规则覆盖率和负迁移率，并分别设置衰减、权限与删除策略。

**相关知识点：** Episodic Memory、Semantic Memory、Case-based Reasoning、Memory Consolidation、知识归纳、Provenance、适用条件、反例、负迁移。

### CTX-043 · 长期记忆如何避免无限增长？

> 稳定 ID：`CTX-043`｜原题号：43

**长期记忆必须同时控制写入速率、重复数据、保留期限和低价值内容，通过容量预算与生命周期策略把增长限制在可预测范围内。**

1. 入口采用价值门，只允许具有跨会话复用价值、可信证据和明确适用范围的事实或经验进入长期层；原始聊天、临时工具结果、失败计划和低置信推断保留在短期层并按期清理。对每个租户、用户和记忆类型设置条数、字节及每日写入配额，超过阈值时进入候选队列或拒绝，而不是无界扩容。

2. 写入前用稳定memory_id、内容哈希、实体键和语义相似度去重；近义事件合并为带原始引用的分层摘要，冲突事实则保存版本关系，不能错误合并。**压缩减少表示冗余，遗忘降低召回价值，归档降低存储成本，三者解决的问题不同**。高价值原文进入冷存储，默认索引仅保留活跃摘要和必要元数据。

3. 周期任务依据TTL、最后使用时间、命中后成功率、置信度和法定保留级别执行降权、压缩、归档或墓碑删除，并同步清理向量、倒排、缓存和对象副本。系统监控净增长率、重复率、每租户容量、低价值命中率、压缩率、清理积压及误删率；预测达到容量水位前触发告警和限流，通过历史回放验证清理不损害任务成功率。

**相关知识点：** 容量预算、写入配额、Deduplication、Memory Compression、TTL、Memory Decay、冷存储、墓碑删除、数据保留策略、容量水位。

### CTX-044 · Agent 如何判断哪些内容值得写入长期记忆？

> 稳定 ID：`CTX-044`｜原题号：44

**Agent应通过持续价值、可信度、复用概率、独特性和保存风险进行多维评分，只有证据充分且预期收益高于治理成本的内容才写入长期记忆。**

1. 候选生成由用户明确确认、任务成功、错误纠正、项目里程碑或重复模式触发，抽取事实、偏好、约束、决策和经验。持续价值判断其跨会话有效期，复用概率判断未来任务命中可能，独特性排除已有内容，可信度依据用户确认、权威来源或工具结果，风险则考虑敏感性、权限和误用后果。

2. 可建立可解释评分：价值分由稳定性、复用性、结果影响和证据强度加权，扣除重复度、敏感度、过期概率及维护成本。硬规则优先于分数：认证秘密禁止写入，缺少主体或来源的内容进入隔离区，高风险个人信息要求明确授权。**模型判断只负责提出候选，不能同时充当证据和最终审批者。**

3. 达到高阈值的低风险候选可自动发布，中间区间需要更多案例或人工确认，低分内容留在短期层并过期。每条正式记录保存评分分解、来源、置信度、适用范围、版本和TTL。通过后续召回是否被采用、任务是否成功、用户是否纠错更新阈值，评测写入接受率、有效命中率、错误写入率、负迁移率和单位有效记忆成本。

**相关知识点：** Memory Scoring、候选记忆、价值门、证据等级、数据最小化、硬规则、阈值校准、Human-in-the-loop、负迁移、TTL。

### CTX-045 · Memory Compression 应该如何设计？

> 稳定 ID：`CTX-045`｜原题号：45

**Memory Compression应设计为可回溯、分层和任务感知的压缩服务，在减少Token与存储成本的同时，严格保护事实、约束、异常和证据关系。**

1. 输入先按事件、实体和任务阶段规范化，使用内容哈希、稳定ID及语义聚类去除完全重复和近义记录；不同时间、权限或适用条件的内容不得误合并。随后抽取目标、用户确认事实、硬约束、关键动作、工具结果、错误、决策依据和未决事项，把冗长原文转为结构化槽位，而非直接生成自由文本摘要。

2. 长轨迹按事件摘要、阶段摘要、任务摘要逐级聚合，每个摘要保存source_ids、覆盖时间、模型版本、权限交集和内容哈希。**压缩产物是派生视图，不是新的权威事实源**；数字、否定、截止时间、ACL、失败原因及引用作为强制保留字段，通过规则比对和事实一致性模型校验，冲突项显式并列。

3. 检索默认返回短摘要和来源，置信度不足、用户追问或高风险决策时按引用逐层展开原文；这样兼顾低成本与可审计性。压缩任务采用异步队列、幂等键和版本化发布，质量不达标时保留旧版本。评测压缩率、事实保留率、约束遗漏率、引用可达率、下游任务成功率与Token节省，并针对数字、冲突和多跳问题建立回归集。

**相关知识点：** Memory Compression、结构化抽取、语义去重、Hierarchical Summary、Source ID、派生视图、事实一致性、Progressive Retrieval、摘要漂移。

### CTX-046 · Memory Summary 和原始记忆如何关联？

> 稳定 ID：`CTX-046`｜原题号：46

**Memory Summary是原始记忆的版本化派生视图，通过稳定ID、覆盖范围和哈希建立可追溯关联，不能替代原始证据。**

1. 原始事件用immutable event_id保存主体、内容、时间、来源、租户、ACL和版本；摘要记录summary_id、source_event_ids、起止时间、层级、模型、Prompt版本及哈希。多级摘要通过parent_summary_id组成有向无环图，使任务摘要能下钻到阶段摘要、事件摘要和原文。

2. 摘要权限取全部来源权限的安全交集，来源被删除、撤回、纠正或权限变化时，由反向索引定位摘要并标记stale，重建后发布新版本。**摘要中的关键事实应映射到source_id，否则只能标为模型概括，不能作为确定证据。**原始记录不因摘要生成而被覆盖。

3. 检索先返回摘要以节省Token，并携带source_id、时间、置信度和版本；涉及数字、冲突、审计或高风险动作时展开原文。存储层维护引用完整性和孤儿检测，更新事件幂等传播到摘要索引及缓存。评测引用可达率、来源覆盖率、事实一致性、陈旧摘要命中率、展开后准确率和删除传播延迟。

**相关知识点：** Memory Summary、Event Sourcing、Source ID、Lineage、派生视图、反向索引、Staleness、引用完整性、版本化摘要、Progressive Retrieval。

### CTX-047 · 动态长期记忆的存储结构应该如何设计？

> 稳定 ID：`CTX-047`｜原题号：47

**动态长期记忆应分离原始事件、规范记录和派生索引，以稳定memory_id连接各层，支持检索、纠错和删除。**

| 层次 | 主要内容 | 推荐载体 |
| --- | --- | --- |
| 原始事件 | 对话、工具结果 | 对象存储 |
| 规范记录 | 主体、版本、ACL | 关系库 |
| 派生索引 | 关键词、向量、关系 | 搜索与向量库 |

1. 核心记录包含memory_id、主体、租户、类型、内容、来源、置信度、有效期、ACL、状态和版本。事实、偏好、情景、经验与摘要使用不同类型约束；索引仅保存可重建字段，原始证据保持不可变，向量库不能作为唯一事实源。

2. **动态更新采用追加版本和supersedes边，不原地覆盖旧记录**。事件以event_id幂等写入，通过Outbox或CDC更新关键词、向量和图索引；查询依据active_version读取一致视图。冲突事实并存并标注来源与有效区间，删除先写墓碑，再清理索引和缓存。

3. 数据按tenant_id和subject_id分区，按时间及重要度分层，敏感字段加密。Embedding升级构建影子索引，校验数量、哈希和Recall后切换。评测幂等性、读取一致性、索引新鲜度、冲突解析率、删除完整性、P95与成本，并定期执行索引对账。

**相关知识点：** Event Sourcing、Memory Schema、Polyglot Persistence、Outbox、CDC、Supersedes、Bitemporal Data、影子索引、墓碑删除、索引对账。

### CTX-049 · 动态记忆如何进行过期清理？

> 稳定 ID：`CTX-049`｜原题号：49

**动态记忆清理应由有效期和保留策略驱动，采用“查询过滤、写入墓碑、异步删除、跨存储对账”的流程。**

1. 记录包含创建时间、有效期、最后访问时间、保留级别、legal_hold和状态。TTL按类型配置：临时状态随任务过期，项目事实按版本失效，用户偏好在更改前有效，审计记录遵循法规期限。查询端始终过滤expired、revoked和tombstoned状态，避免清理延迟使旧数据被召回。

2. 清理器按tenant和时间桶扫描到期记录，先写墓碑和delete_event，再通过队列幂等删除向量索引、倒排索引、缓存、对象及摘要。**删除事件必须先于物理清理生效，使读路径立即不可见，并保留重试与审计依据。**存在legal_hold或被有效摘要引用的记录进入待处理队列。

3. 消费者以delete_event_id去重，失败进入退避重试和死信队列；定期比较主库墓碑、索引和对象副本，发现孤儿立即补偿。备份采用密钥擦除或到期轮转。测试覆盖时钟偏差、重复删除、部分失败和索引延迟，监控过期命中率、清理积压、删除P95、孤儿率、误删率及删除证明完整性。

**相关知识点：** TTL、Retention Policy、Legal Hold、墓碑删除、Delete Event、幂等消费、死信队列、索引对账、Crypto-shredding、删除证明。

### CTX-050 · Agent Reflection 结果是否应该进入长期记忆？

> 稳定 ID：`CTX-050`｜原题号：50

**Reflection结果不应默认进入长期记忆；只有被执行证据验证、能够跨任务复用且风险可控的经验，才适合经过质量门后沉淀。**

1. Reflection本质上是模型对任务轨迹的解释，可能包含合理归因，也可能产生事后合理化或虚构因果。因此原始反思只进入候选区，并关联任务输入、采取动作、工具结果、评价分数、错误日志和模型版本。用户明确事实与工具观测单独保存，不能因反思文本语气确定而提升可信等级。

2. 候选经验需明确适用条件、失败原因、改进动作和完成标准，通过重放、单元测试、独立评价或多个同类任务复现后再晋级；高风险策略要求人工审核。**长期记忆应保存可验证的经验单元和证据引用，而不是模型不可审计的思维链。**仅对一次案例有效、无法复现或与外部事实冲突的反思应淘汰。

3. 正式记录保存source_trace_ids、置信度、成功与失败次数、适用范围、版本和有效期；召回后继续记录采用结果，出现反例时降权、缩小范围或撤销。可稳定抽象为流程的经验进入Skill候选，个案经历保留为Episodic Memory，两者不可混存。评测错误晋级率、复现通过率、命中后成功率、负迁移率和人工纠错率。

### CTX-051 · 动态记忆如何避免错误经验累积？

> 稳定 ID：`CTX-051`｜原题号：51

**动态记忆必须将候选生成、证据验证、正式发布和反馈淘汰分离，避免模型自评形成自我强化的错误经验闭环。**

1. 新经验默认进入隔离候选区，记录任务输入、采取动作、工具结果、评价信号、模型版本、适用条件和来源Trace。写入前执行Schema、事实一致性、重复、冲突、权限及敏感信息检查；一次成功、语言自洽或模型反思不能作为充分证据，关键经验必须通过重放、测试、用户确认或多个独立案例复现。

2. 正式记录保存置信度、成功次数、失败次数、证据强度、适用范围、版本和有效期。**召回排序应把可信度与适用性作为独立信号，不能仅凭语义相似度反复使用同一错误经验**。高风险任务只允许高置信经验进入参考区，并要求外部校验；冲突记录并存，禁止低可信新内容覆盖用户确认事实。

3. 每次命中后记录是否采用、任务是否成功及是否被纠正，反例触发降权、缩小适用域、隔离或撤销，而不是只累计成功样本。定期用时间切分测试集审查高命中经验，检测来源集中、反馈回路和概念漂移；监控错误晋级率、负迁移率、用户纠错率、撤销延迟及记忆多样性，异常批次可按来源和版本回滚。

### CTX-053 · Skill 是否属于静态长期记忆？

> 稳定 ID：`CTX-053`｜原题号：53

**Skill可视为广义静态能力资产，但不应归入Memory；它保存可执行方法，而不是主体事实或经历。**

| 维度 | Skill | 静态知识或Memory |
| --- | --- | --- |
| 核心内容 | 步骤、工具、校验和回滚 | 事实、概念、偏好和经历 |
| 使用方式 | 任务匹配后执行 | 检索后作为证据 |
| 更新门槛 | 测试、审核、版本发布 | 来源验证、纠错或过期 |

1. Skill包含适用条件、输入输出契约、步骤、工具依赖、异常分支、完成标准和安全边界，用于稳定复现同类任务。静态知识回答“什么是事实”，Memory回答“用户或任务发生过什么”。因此Skill更接近程序、策略或操作手册，不是语义记忆中的事实条目。

2. **经验记忆可成为Skill的证据，但必须经过跨案例抽象、去个性化、独立测试和风险审核，不能直接复制为流程。**单次成功可能依赖环境；用户令牌、权限或偏好不能固化进Skill。Skill应具有版本、依赖、所有者、回归集和回滚方式，高风险动作仍需授权。

3. 运行时先匹配Skill，再从知识库和Memory检索事实与个体参数。三者应分命名空间和治理流程：Skill评测成功率、确定性和副作用；知识评测事实准确率；Memory评测有效命中率、错误率和隐私风险。分离能避免事实更新误改流程，避免个人记忆污染能力。

**相关知识点：** Skill、Static Knowledge、Long-term Memory、Semantic Memory、输入输出契约、经验抽象、能力路由、版本发布、回归测试、运行时授权。

### CTX-055 · 静态记忆和动态记忆如何联合检索？

> 稳定 ID：`CTX-055`｜原题号：55

**联合检索应先分域召回，再校准分数和可信重排，使静态知识提供权威事实，动态记忆补充任务情境。**

| 来源 | 排序重点 | 典型作用 |
| --- | --- | --- |
| 静态记忆 | 权威性、版本、时效 | 提供制度与领域事实 |
| 动态记忆 | 主体匹配、置信度、近期性 | 提供偏好、状态与经验 |

1. Query Router抽取用户、租户、实体、任务类型、时间和意图，判断是否需要两域。静态域按ACL、active_version和有效期过滤，再做BM25与向量召回；动态域按subject_id、ACL、状态和有效期过滤，再结合语义、近期性、重要度及成功率召回，避免跨主体经验混入。

2. 两域分数不可直接比较，可用RRF、归一化或排序模型融合；Reranker评估相关性、来源、权威性、时效、置信度和适用范围。**客观规则冲突时优先权威文档，动态记忆只能补充背景，不能覆盖事实。**按来源去重并保留冲突证据。

3. Context Builder按Token预算保留事实与个体证据，附带source_id、版本、时间及置信度；不足时返回无可靠结果。离线评测分域Recall@K、融合NDCG和冲突准确率，监控有效使用率、负迁移、过期命中、跨租户泄漏、P95与成本，并按查询类型调整配额。

**相关知识点：** Federated Retrieval、Query Router、Hybrid Search、RRF、Score Calibration、Reranker、Memory Scoring、冲突消解、动态配额、NDCG。

### CTX-057 · 如何解决不同记忆来源之间的冲突？

> 稳定 ID：`CTX-057`｜原题号：57

**记忆冲突应通过来源等级、时间有效性、主体匹配和证据强度显式消解，不能用向量相似度或“最后写入覆盖”简单决定。**

1. 记录保存主体、属性、值、来源、证据、置信度、有效期、租户、ACL和版本。写入时做实体归一与声明比对，区分真正矛盾、时间变化、范围不同和表达差异；旧地址与新地址属于时间更新，测试与生产环境属于范围差异，不应误判为互斥事实。

2. 优先级通常是用户对自身事实的确认、权威系统或工具观测、验证文档、多次成功经验、模型推断；同等级再比较时效、证据和适用条件。**来源可信度必须与事实类型绑定，组织制度由权威文档决定，个人偏好由本人确认决定。**高风险或证据接近时保留并列记录并请求确认。

3. 结果以supersedes、contradicts或scoped_to关系追加，不覆盖证据；被取代内容退出默认召回，但可追溯。Reranker输出选择依据和冲突标记，Prompt只注入当前有效值及必要反证。评测冲突检测召回率、选择正确率、未决升级率、过期值命中率和用户纠错率，并复核高频冲突实体。

**相关知识点：** Conflict Resolution、Provenance、Source Authority、Bitemporal Data、Supersedes、Contradiction Detection、置信度校准、Human-in-the-loop。

### CTX-058 · Memory Rerank 应该基于哪些特征？

| --- | --- |

### CTX-060 · 记忆检索延迟过高如何优化？

> 稳定 ID：`CTX-060`｜原题号：60

**记忆检索优化应先用Trace定位过滤、查询、融合、重排或网络瓶颈，再按召回质量约束实施并行、裁剪、缓存和索引调优。**

1. 埋点拆分Query Rewrite、权限过滤、BM25、ANN、RRF、Reranker、原文读取和序列化耗时，观察P50、P95、P99、QPS、候选量、分片倾斜及超时率。先确认是单查询慢、排队拥塞还是跨服务调用过多；使用真实流量回放和火焰图定位，不能只依据平均延迟更换向量数据库。

2. 查询链路并行执行稀疏与稠密召回，为各路设置独立超时、熔断和候选上限；简单查询跳过改写或Rerank，复杂查询再升级。ANN侧调节HNSW efSearch、IVF nprobe、分片、副本和量化，Reranker采用批处理、蒸馏、小模型级联及早停。**降低Top-K必须用Recall回归证明，不能以漏召回换取表面低延迟。**

3. 缓存查询Embedding、权限过滤结果和高频候选，但缓存键必须包含tenant、ACL版本、索引版本、模型和TTL，命中后仍验证授权及新鲜度。冷热分层让近期高价值记忆驻留热存储，批量请求和连接池降低网络开销。验收同时比较P95、Recall@K、NDCG、错误记忆率和成本，并为单路超时设计可观测降级。

**相关知识点：** Distributed Tracing、P95/P99、HNSW、IVF、Reranker Distillation、批处理、早停、权限缓存、冷热分层、熔断降级。

### CTX-061 · 企业级 Agent 的 Memory Service 应该如何设计？

> 稳定 ID：`CTX-061`｜原题号：61

**Memory Service应写入、检索、更新、删除和审计，并以租户隔离、版本治理、读降级和写恢复为基础。**

### CTX-062 · 多 Agent 如何共享长期记忆？

> 稳定 ID：`CTX-062`｜原题号：62

**多Agent应通过Memory Service和授权命名空间共享记忆，以事件和版本同步，不能互相复制Prompt或开放全量存储。**

| 作用域 | 内容 | 访问原则 |
| --- | --- | --- |
| Agent私有 | 局部状态 | 仅所属Agent |
| 团队共享 | 任务事实、公共经验 | 按项目授权 |
| 用户私有 | 偏好与历史 | 按主体授权 |

2. 写入采用候选、审核、发布三阶段，事件总线广播创建、取代和删除事件，消费者以event_id幂等更新缓存。**共享记忆必须存在唯一权威记录和版本，Agent本地副本只能作为可失效缓存。**并发修改使用乐观锁，冲突记录并列并交由规则或人工消解。

3. 检索先按scope、主体、Agent身份和ACL过滤，再按相关性、时效、来源及范围重排；返回memory_id和版本，便于反馈与撤销。审计记录访问主体、任务和操作。评测共享命中率、跨Agent成功率、冲突率、同步延迟、陈旧副本命中、越权访问和错误传播半径。

**相关知识点：** Shared Memory、Memory Service、Namespace、Service Identity、授权视图、Event Bus、乐观锁、版本水位、缓存失效、审计追踪。

### CTX-063 · 如何实现 Memory 的高可用和容灾？

> 稳定 ID：`CTX-063`｜原题号：63

**Memory高可用应保证读路径可降级、写事件不丢失、派生索引可重建，并以明确RPO和RTO设计跨可用区及跨地域恢复。**

1. API网关和无状态检索服务跨可用区部署，使用健康检查、负载均衡和自动扩缩容；关系库采用主备或多副本，事件队列开启持久化与跨区复制，对象存储启用版本和校验。向量、倒排及缓存均视为派生数据，可从事务记录和事件日志重建，不能成为唯一事实源。

3. 跨地域方案按业务选择热备、温备或冷备，定期备份事务库、对象和密钥元数据，并验证恢复后的ACL、墓碑与索引一致性。演练覆盖单实例、整区、队列积压、误删除、索引损坏和密钥故障；监控可用性、复制延迟、RPO、RTO、恢复成功率、索引新鲜度及降级比例，并记录切换和回切审计。

**相关知识点：** High Availability、Disaster Recovery、RPO、RTO、Outbox、事件重放、版本水位、派生索引、熔断降级、故障演练。

### CTX-064 · 如何保证长期记忆的数据安全和合规性？

> 稳定 ID：`CTX-064`｜原题号：64

**记忆安全应落实数据最小化、用途限制、服务端授权、全链路加密、可证明删除和持续审计，不能依赖Prompt声明保护数据。**

1. 写入前进行数据分类，确认用途、授权依据、主体、地域、保留期和删除条件；只保存完成任务必需的字段。密码、令牌和私钥禁止进入记忆，敏感个人信息默认拒绝或脱敏。记录携带tenant_id、subject_id、purpose、classification、ACL和TTL，向量、摘要及日志同样属于受保护派生数据。

2. 身份接入企业IAM，采用最小权限、RBAC与ABAC组合；检索前执行tenant和ACL预过滤，读取原文及引用展开时再次授权。传输使用TLS，静态数据用租户或敏感域密钥加密，密钥由KMS轮换。**缓存键、搜索索引和Embedding必须继承原记录权限，不能成为绕过主库控制的旁路。**

3. 所有创建、查询、修改、导出和删除记录主体、用途、资源、策略版本与结果，审计日志防篡改并限制访问。到期或用户删除请求先写墓碑，再清理主库、向量、倒排、缓存、摘要和可控备份，生成删除证明。执行权限复核、跨租户测试、密钥演练、数据泄漏检测和影响评估，监控越权率、敏感数据写入率、删除延迟及审计缺口。

### CTX-066 · MCP、RAG、Memory 三者在 Agent 架构中的职责边界是什么？

> 稳定 ID：`CTX-066`｜原题号：66

**MCP解决外部能力如何被标准化调用，RAG解决权威知识如何被检索并引用，Memory解决用户与任务状态如何跨轮延续。**

| 组件 | 核心对象 | 主要输出 |
| --- | --- | --- |
| MCP | 工具、资源和提示接口 | 可调用能力及结果 |
| RAG | 文档与领域知识 | 带来源的证据 |
| Memory | 偏好、状态和历史经验 | 主体相关上下文 |

1. MCP定义Agent与外部服务的能力发现、参数Schema和调用协议，不保证工具结果正确，也不等于知识库；授权、审批、超时、幂等和副作用仍由宿主负责。RAG从治理后的数据源召回证据，关注版本、ACL、来源、时效、Recall和引用准确率，不保存个体会话历史。

2. Memory保存用户事实、偏好、任务状态及验证经验，强调主体、置信度、有效期、版本和删除权；它不能替代组织制度，也不应保存工具秘密。**工具返回可以成为RAG更新或Memory候选的证据，但必须经过来源、权限和价值检查，不能自动沉淀。**

3. 执行时先由Memory恢复约束，再用RAG获取事实，最后通过MCP调用工具；结果更新任务状态，稳定经验进入候选记忆。三类数据使用独立命名空间和审计策略，由Context Builder组装。评测工具成功及副作用、检索与引用质量、记忆有效命中及负迁移，避免单一指标掩盖职责错误。

**相关知识点：** MCP、RAG、Memory、Tool Calling、Resource、Provenance、Context Builder、能力发现、候选记忆、职责边界。
