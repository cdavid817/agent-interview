### 1. 哪些反思结果值得沉淀为Skill？

**只有可重复、可验证、边界明确且能显著改善任务指标的反思结果，才适合从一次性经验升级为Skill。**

1. 候选经验应在同类任务中多次出现，能够描述稳定的触发条件、输入输出契约、操作步骤、异常分支和完成标准。例如固定的代码审查流程、数据库迁移检查或文档发布规范，具备程序化价值；某个用户偏好、单次故障细节和未经证实的猜测更适合记忆或案例库。**Skill表达可执行方法，Memory保存事实与经历，二者不能混用。**

2. 晋级前建立收益与风险门槛：在独立测试集上比较启用前后的成功率、返工率、时延、Token和工具调用成本，确认提升并非样本偶然性；检查权限边界、幂等性、失败恢复和副作用。涉及删除、付款、生产发布等高风险动作，即使效果稳定，也必须保留显式审批，不得把授权固化进Skill。

3. 沉淀内容应包括适用范围、不适用条件、依赖、参数、步骤、校验脚本、回滚方式、示例与版本，并由维护者审核。上线后采用灰度或影子执行，记录命中率、成功率和负迁移率；环境、接口或政策变化时触发重测。若经验仅提升某个狭窄案例、难以验证或频繁产生例外，应继续作为候选规则观察，而不是过早抽象。

**相关知识点：** Skill抽象、经验晋级、输入输出契约、完成标准、独立评测、幂等性、灰度发布、负迁移、版本治理、人工审批。

### 2. Top-K应该如何确定？

**Top-K应由召回覆盖、精排能力、上下文预算和查询置信度联合确定，生产系统不宜对所有查询使用同一常数。**

1. 区分召回K、精排K和最终注入N：第一阶段K要足以让标准相关记忆进入候选，精排阶段只处理可承受的候选量，最终N受Token预算和证据冗余限制。用Golden Dataset扫描K值，绘制Recall@K、Precision@K、MRR、P95和成本曲线；选择Recall增益开始趋缓且延迟仍达标的拐点，而不是凭经验取5或10。

2. K应按查询自适应：精确实体或高分断层明显时可减小，短而含混、复合意图或多跳问题可扩大；候选分数整体偏低时，不应通过增加K强行注入无关记忆。**召回更多只提高覆盖上限，不保证最终答案更好，冗余和冲突候选会造成上下文污染。**可根据Top-1与后续分差、分数熵、查询类型和用户记忆规模做动态早停。

3. 混合检索为各通道预留候选配额，融合后去重，再由Reranker选择最终N；相邻同源记忆可合并，冲突项必须成组保留或排除。线上A/B观察任务成功率、错误注入率、上下文Token和延迟，并按查询类型分桶。若模型、切片、索引规模或数据分布变化，应重新校准K和阈值，保留低置信不召回的安全出口。

**相关知识点：** Recall K、Rerank K、Final N、Recall@K、Precision@K、收益拐点、分数熵、动态早停、候选配额、上下文污染、A/B测试。

### 3. Prompt Injection 攻击如何防御？

**Prompt Injection无法仅靠提示词消除，必须用不可信数据隔离、最小权限、动作校验、秘密隔离和持续红队形成纵深防御。**

1. 将用户输入、网页、邮件、RAG文档和工具结果标记为不可信数据，以明确边界与来源注入；System策略、工具定义和授权状态位于更高信任层，外部文本不得改变。检索前执行tenant_id与ACL过滤，敏感信息只保存在模型不可见的凭证服务中。检测器可识别攻击模式，但只能用于加风险分，不能作为唯一防线。

2. 工具通过短期、最小作用域凭证执行，参数必须符合Schema、资源白名单与业务策略；读写工具分离，高风险删除、转账、发送和权限变更要求确认。模型只提出动作建议，由Policy Enforcement Point在代码层决定是否允许。**即使模型被诱导，只要它拿不到秘密且无权执行危险动作，攻击影响仍被限制。**

3. 输出侧做泄漏检测、引用检查和目的地限制，但不能替代前置控制；Memory写入阻断持久化恶意指令。建立直接注入、间接注入、编码混淆、多跳工具和数据外传测试集，持续红队并记录攻击链trace。监控危险工具拦截、异常外连和确认绕过；事件发生时撤销凭证、隔离会话、清理污染记忆并复盘。

**相关知识点：** Prompt Injection、间接注入、信任边界、最小权限、凭证隔离、Policy Enforcement Point、参数白名单、高风险确认、数据外传、红队测试。

### 4. Agent如何避免上下文污染？

**Agent避免上下文污染的关键是建立来源分区、信任边界、权限与版本过滤、相关性排序和最小上下文组装机制。**

1. Prompt Builder将System、用户目标、会话状态、Memory、RAG和Tool结果分区，每个片段标记source、trust_level、timestamp、version、ACL和token_count。System与当前任务属于保护区，外部网页和工具输出只是不可信数据。检索前强制执行tenant、权限、有效期和版本过滤，避免越权、过期或删除内容进入候选。

2. 候选按相关性、权威性、新鲜度和唯一性精排，按文档与语义去重，冲突项并置标注，低置信内容不注入；历史只保留未决事项和确认事实，工具日志提取关键字段。**增加窗口不会自动降低污染，必须先删无关信息，再抽取证据，最后才做生成式摘要。**摘要保留原文引用。

3. 工具调用由代码执行Schema、白名单、最小权限和高风险确认，即使上下文含恶意指令也限制影响。trace记录最终片段、排序和裁剪原因，通过逐层消融定位污染来自History、Memory、RAG还是Tool。监控证据密度、冲突率、过期命中、错误引用和工具误调用；异常时重新检索、回退原文或清空受污染状态。

**相关知识点：** Context Pollution、信任边界、来源分区、权限过滤、版本过滤、Context Ranking、语义去重、冲突标注、分层消融、最小权限。

### 5. Function Calling的参数最终如何进入模型？

**Function Calling参数以工具Schema作为模型输入约束，由模型生成结构化arguments；工具执行结果再作为tool消息回填上下文，形成完整调用闭环。**

1. 应用提供工具name、description和JSON Schema，模型将定义编码进上下文；模型依据问题和Schema生成assistant工具调用，其中arguments是JSON或结构化对象。它不直接执行函数，也不把参数写入用户Prompt，而是预测调用意图。调用由call_id标识。

2. 编排器解析arguments，执行Schema、类型、枚举、长度、业务规则和权限校验；高风险操作要求确认，失败则返回结构化错误。**模型生成的参数属于不可信提议，只有执行器校验并授权后才能进入真实函数。**执行层将合法参数转换为语言对象调用API，并记录call_id、幂等键和审计日志。

3. 执行结果封装为call_id对应的tool消息，包含status、payload或error，再与原调用发送给模型；模型据此继续、重试或回答。长结果外置并只注入摘要与引用。测试覆盖字段缺失、类型错误、恶意参数、并行、超时、重复执行和结果注入，指标包括参数通过率、工具成功率及误执行率。

**相关知识点：** Function Calling、Tool Schema、arguments、call_id、JSON Schema、参数校验、幂等键、tool消息、权限审批。
