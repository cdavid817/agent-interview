### 如果企业项目有几十万行代码，Coding Agent如何快速定位和理解相关代码上下文？（DeepSeek一面）

大型仓库不能整库加载，应采用**结构化索引、混合检索、调用图扩展和渐进式上下文**，先定位候选，再逐步读取证据。

1. 按Commit构建文件、符号、AST、类型、Import、调用图、测试和Git历史索引，生成Repo、Module、File和Symbol摘要；记录语言、路径、版本与权限。
2. 从需求提取实体、错误和接口，BM25命中符号、路径与错误码，Embedding召回语义实现；按模块、分支和权限过滤，融合后由Reranker排序。
3. 对高分Symbol沿定义、引用、调用、实现、继承和测试扩展一至两跳；LSP提供语义导航，动态调用通过配置、运行时Trace和Git证据补全。
4. 上下文按Repo Map、签名、代码片段、调用链、测试和约束逐层加入，设置Token预算与去重；仅在需要时展开完整函数或文件。
5. 修改前验证分支与Commit，修改后检索受影响引用，执行影响分析、测试、静态检查和CI；索引按Commit Diff增量更新。

效果以定位Recall@K、MRR、上下文Precision、完成率、延迟和Token衡量，并以真实缺陷、跨文件及长尾任务构建评测集。

**相关知识点：** Hybrid Search、Symbol Index、AST、LSP、Call Graph、Repo Map、渐进式上下文、Change Impact Analysis、增量索引。

### 多租户企业级Agent平台数据隔离、权限隔离、资源隔离完整方案（Agent高级）

多租户方案应把TenantID作为**身份、数据、执行与计费的强制边界**，在网关、存储和目标系统重复校验。

1. 身份权限：用户、Agent、服务和令牌绑定TenantID；SSO与Workload Identity分离，Policy Engine取各方权限交集，RBAC给基线、ABAC收窄。
2. 数据隔离：按敏感度选择独立集群、Schema或RLS；对象、向量、缓存、消息、Memory、Artifact和备份均含租户边界。
3. 运行隔离：每任务或租户使用独立容器、卷、网络、队列和密钥，禁止宿主Socket与跨租户挂载；高敏租户采用专属KMS和资源池。
4. 资源隔离：按租户设置并发、QPS、Token、GPU、CPU、内存、存储和Tool配额，使用公平队列、背压与Bulkhead防Noisy Neighbor，并记录成本。
5. 观测治理：Trace、指标和审计按租户授权并脱敏，对跨租户、配额异常和批量导出告警；备份、删除、密钥轮换保持隔离。

跨租户运维使用Break-glass角色、JIT凭证、双人审批和审计。通过随机TenantID、缓存投毒、向量越权、消息重放和管理员绕过测试验证。

**相关知识点：** TenantID、RLS、ABAC、Workload Identity、KMS、Network Policy、Quota、公平调度、Bulkhead、Noisy Neighbor。

### Coding Agent为什么不能直接把整个代码仓库加载到大模型？

Coding Agent不能直接加载整个仓库，原因不只是窗口有限，**信号密度、推理质量、成本、安全和版本一致性**也会恶化。

1. 大型仓库可达百万行，Token远超窗口；即使支持长上下文，注意力也会被无关文本稀释，产生“中间信息遗失”和错误关联。
2. 全量输入增加首Token延迟、推理费和缓存压力，每次提交都重复传输未变化内容；高并发下难以满足交互SLA。
3. 仓库可能含密钥、客户数据和受限代码，全量加载违反数据最小化与最小权限；第三方文件中的Prompt Injection还会扩大攻击面。
4. 分支、Commit、子模块和生成物可能版本不同；未绑定版本的快照会混合过期实现，导致定位和修改依据错误。
5. 任务通常只依赖局部符号、调用链、配置和测试。应构建Symbol、AST、依赖图、BM25与Embedding索引，通过Repo Map定位候选，再沿定义、引用和调用关系扩展。

组装时保留路径、Commit、行号和来源，执行去重、Rerank、Token预算与分层摘要；再根据编译、测试和Observation补充，使模型获得**最小充分上下文**。

**相关知识点：** Context Window、注意力稀释、Lost in the Middle、Repo Map、Symbol Index、AST、Hybrid Search、渐进式上下文、最小权限。

### Coding Agent如何建立代码仓库索引（Repository Index）？

Repository Index应包含**文本、符号、语法、关系和语义索引**，并与仓库、分支、Commit绑定；单一向量库无法支撑精确定位。

1. 首次扫描依据.gitignore、语言和安全策略排除二进制、生成物、依赖、密钥与无效文件；计算内容哈希，记录仓库、分支、Commit、路径、语言和权限。
2. 使用Tree-sitter或编译器前端解析AST，按函数、类、接口和配置块切块，提取Symbol、签名、定义、引用、Import、继承、实现与行号；失败时降级为文本。
3. 倒排索引支持路径、标识符和错误码检索；代码与摘要生成Embedding；定义—引用、调用、依赖、测试关系写入图索引，形成Repo Map。
4. 查询时并行执行BM25、向量、Symbol和图遍历，用RRF或学习排序融合，再结合路径、调用相关性、新鲜度和权限Rerank。
5. 以Git Diff识别新增、修改、删除和重命名，仅重建受影响块、符号及邻边；新版本构建后原子切换，并支持失败回滚。

服务需分片、缓存、批量Embedding并隔离租户，监控索引滞后、解析失败率和查询P95。离线使用Recall@K、MRR评估，并确保索引快照与工作树一致。

**相关知识点：** Repository Index、AST、Symbol Index、倒排索引、Embedding、代码图谱、Repo Map、增量索引、原子切换。

### Coding Agent如何构建Call Graph（调用图）？

Call Graph以函数为节点、潜在调用为有向边，用于**跨文件定位、影响分析和上下文扩展**；实现需融合静态分析与运行时证据。

1. 解析依赖、编译参数和源码，用编译器前端、Tree-sitter或LSP提取定义、调用、Import、类型、继承和实现，为Symbol生成绑定Commit与签名的稳定ID。
2. 直接调用通过名称、作用域、参数和类型绑定；接口与虚方法采用类层次或快速类型分析生成候选边，标注置信度、源码位置及静态或动态来源。
3. 反射、动态代理、依赖注入、回调和配置调用难以静态确定，应解析注解、容器绑定与路由表，并结合APM Trace或插桩补全实际边。
4. 图中维护caller、callee、模块和权限，支持向上追入口、向下展影响、限深、环检测和路径排序；查询结合相关性、置信度与频次控制膨胀。
5. 依据Git Diff重解析变更符号，删除旧边并重算受类型、继承和依赖影响的邻域；新图原子切换，并检查悬空节点和工作树一致性。

Call Graph表示“可能调用”，不等于真实执行顺序。Agent还需结合CFG、数据流、测试和业务终态验证，避免把低置信候选当成事实。

**相关知识点：** Call Graph、CHA、RTA、动态插桩、APM Trace、依赖注入、边置信度、CFG、增量图更新。

### 什么是Change Impact Analysis？如何评估一次代码修改的影响范围？

Change Impact Analysis识别变更影响的**调用者、数据、接口、配置、测试、部署单元和业务流程**，以证据划定验证范围，而非统计文件数。

1. 从Git Diff提取签名、控制流、数据结构、配置和依赖变化，映射到Symbol；区分内部实现、公共契约、数据库Schema、安全策略和跨服务协议。
2. 在定义—引用、Call Graph、Import、继承、数据流、API/IDL、Topic、配置和部署图中双向遍历直接与传递依赖；设置限深、环检测和节点预算，保留路径证据。
3. 融合静态关系与Trace、覆盖率、调用频次、Git共变和Code Ownership。静态分析保证召回，动态证据排序；未观测不能视为无影响。
4. 按契约破坏、图距离、边置信度、流量、数据敏感度和故障半径评分，输出受影响Symbol、服务、接口、数据库、消费者、测试及负责人，标注确定、可能和未知。
5. 按风险运行单测、集成、契约测试、静态检查和安全扫描；高风险增加回放、Shadow、灰度与回滚。数据库和消息Schema需兼容性检查。

结果记录基准Commit、依赖版本和路径，随证据增量更新。用历史缺陷覆盖、测试召回率、误报、漏报事故及验证成本评估。

**相关知识点：** Change Impact Analysis、语义Diff、依赖图、数据流、契约测试、Git共变、故障半径、风险评分、测试选择。

### Coding Agent如何结合RAG提升大型代码仓库的理解能力？

Code RAG把任务转换为**可追溯的代码证据**，通过多路检索、结构扩展和动态重检索，在大仓中获得最小充分上下文。

1. 按函数、类、接口和配置切块，保存路径、Symbol、签名、定义/引用、Commit与权限；建立BM25、Embedding、AST/Symbol、调用图和分层摘要索引。
2. 从任务提取标识符、错误码、业务意图和验收条件并改写查询；精确词项走BM25/Symbol，模糊意图走Embedding，跨文件关系沿调用、继承、配置与测试图扩展。
3. 候选用RRF融合，再结合路径、图距离、新鲜度、Git共变、频次和权限Rerank；去重并限制单文件占比，避免相似片段挤占窗口。
4. 上下文保留目标代码、契约、类型、调用者/被调用者、配置和测试，附路径、行号及Commit。稳定模块用摘要，待修改代码保留原文，并设置Token预算。
5. 根据LSP诊断、编译、测试和Observation重新检索，补齐依赖；证据不足时声明未知，不能依靠参数记忆推断仓库事实。

索引按Git Diff增量更新并绑定工作树，敏感代码检索前过滤权限。离线以Recall@K、MRR、NDCG评估，线上监控无关上下文率、P95、Token与成功成本。

**相关知识点：** Code RAG、语义切块、Hybrid Search、Symbol Index、Graph RAG、RRF、Rerank、动态检索、证据追踪。

### 企业级Coding Agent如何实现毫秒级代码检索？

毫秒级检索依赖**离线计算、在线轻量召回、分层缓存和索引分片**；SLO应针对检索P50/P95，不能混入Embedding构建和LLM推理。

1. 离线解析AST、Symbol、调用图和摘要，预计算代码Embedding；在线只做规范化、路由和ANN/BM25检索。查询向量使用低延迟模型或热点缓存。
2. 倒排索引按仓库、租户、语言和分支分片，向量采用HNSW；元数据过滤前置，避免召回无权限或错误版本结果。
3. 进程内缓存Repo Map、Symbol与热门Posting，分布式缓存查询向量和候选；缓存键包含仓库、Commit、权限与索引版本，防止跨租户和陈旧命中。
4. 第一阶段由BM25、ANN和Symbol并行召回Top K，RRF融合；第二阶段只对少量候选执行Cross-encoder、图距离和新鲜度Rerank，并限制图遍历预算。
5. Git Diff驱动增量索引，批量Embedding，新分片构建后原子切换；服务配置副本、限流、超时与降级，向量异常时回退BM25/Symbol。

监控查询改写、各路召回、融合和Rerank耗时，并观察命中率、索引滞后与Recall@K。优化必须受召回率约束，不能以漏搜关键代码换低延迟。

**相关知识点：** ANN、HNSW、倒排索引、索引分片、多级缓存、两阶段排序、增量索引、原子切换、延迟预算。

### 在Monorepo架构下，Coding Agent如何进行跨模块代码理解？

Monorepo理解依赖**模块边界、构建图和统一版本快照**，先缩小子图，再沿契约与调用扩展，不能把同仓库视为同一上下文。

1. 解析Workspace、构建系统、包清单、目录规则和CODEOWNERS，识别应用、库、共享包、生成目标及测试，建立模块ID、语言、所有者和边界。
2. 以Bazel、Nx、Maven/Gradle等构建图为骨架，融合Import、Symbol引用、API/IDL、配置、Topic和Trace，形成模块—文件—Symbol依赖图。
3. 从任务、错误栈或Symbol定位种子模块，先检索模块内代码，再沿直接/反向依赖、接口实现和测试限深扩展；共享工具只在相关时加入。
4. 索引按模块分片，支持全局Symbol与路径检索。结果依据模块距离、依赖方向、所有权、Git共变、新鲜度和权限Rerank，并限制每个模块候选数。
5. 修改前做影响分析，输出受影响模块、构建目标、消费者和测试；优先验证目标及反向依赖，再按风险扩大。公共契约采用兼容演进。

索引与摘要绑定同一Commit，Git Diff只重建变更模块及邻边。混合语言使用专用Parser/LSP，跨语言边由IDL、构建依赖与Trace连接；低置信关系显示证据。

**相关知识点：** Monorepo、构建图、模块边界、反向依赖、全局Symbol、索引分片、影响分析、兼容演进、跨语言调用。

### 如何评估一个Coding Agent代码定位的准确率和召回率？

代码定位评测以**任务所需证据集合**为真值，衡量是否找全、排前并支持任务；只看目标文件会忽略函数粒度和跨文件依赖。

1. 离线集来自Issue/PR、历史Bug、代码问答和长尾；冻结仓库与Commit，标注必需文件、Symbol、行区间及替代证据，并记录难度与任务。
2. Top K中相关单元为TP，无关为FP，漏召回为FN，则Precision@K=TP/K，Recall@K=TP/(TP+FN)。多真值任务报告微平均与宏平均。
3. MRR衡量首个相关结果位置，NDCG衡量多级相关性；同时报告File、Symbol、Chunk三级指标、无关上下文率和证据覆盖率。
4. 真值不完整时由多名工程师独立标注、仲裁和候选池化，计算一致性；开放任务允许多个最小证据集，评测仅使用冻结代码。
5. 将检索指标与端到端定位、修改成功率、Token、轮数和P95关联。高Recall但噪声大可能降低完成率，必须在统一预算下比较。

结果按语言、仓库规模、任务、难度和跨文件程度切片并报告置信区间。线上点击、后续读取和Trace可辅助验证，但不能替代人工真值。

**相关知识点：** Precision@K、Recall@K、MRR、NDCG、证据覆盖率、宏平均、候选池化、端到端评测、置信区间。

### 大型单体项目无清晰模块划分时，Coding Agent 如何优化代码检索效率？

无模块单体项目应通过**结构与历史证据推导虚拟模块**，再分层检索；目录不是唯一边界，调用、数据和共变关系可形成子图。

1. 解析AST、Symbol、Import、调用、继承、数据表、配置和测试，构建文件—Symbol图；结合Git共变、Ownership与Trace补充隐式耦合。
2. 使用社区发现、强连通分量或图聚类生成虚拟模块，按高内聚低耦合输出入口、接口、实体和负责人。聚类只作导航，不是真实架构契约。
3. 建立Repo/Cluster/File/Symbol分层摘要，查询以业务词、错误码、路径、BM25和Embedding定位候选簇，再在簇内执行Symbol、AST和调用图检索，必要时跨簇扩展。
4. 对公共工具、常量和基础设施设置Hub惩罚或候选上限，避免高连接节点淹没结果；Rerank综合词法、语义、图距离、Git共变、频次、新鲜度和权限。
5. Git Diff增量更新文件、图边和局部聚类，版本绑定Commit。执行时设置Token、节点、深度和探索预算，编译或测试失败再补充。

长期将稳定边界反馈给架构治理，补充包约束、Owner、构建目标和接口测试，但Agent不能擅自重构。用Recall@K、无关上下文率、定位时长、Token和完成率评估。

**相关知识点：** 虚拟模块、社区发现、强连通分量、图聚类、Repo Map、Hub惩罚、Git共变、分层检索、架构治理。

### Coding Agent 解析调用链时遇到多态、动态代理代码如何准确溯源？

多态和代理无法仅凭调用表达式确定目标，应采用**类型约束生成候选、配置解包代理、运行时Trace确认实例**，并标注证据与置信度。

1. 使用编译器或LSP完成名称绑定、类型推断和重载解析；接口与虚方法通过类层次、快速类型或指针分析找可达实现，结合构造点排除不可能类型。
2. 对Spring AOP、JDK/CGLIB代理解析Bean、注解、Qualifier、条件装配、切点和Advisor，建立“调用点—代理—拦截器—目标Bean—方法”分层边。
3. 依赖注入、工厂、ServiceLoader、反射和配置路由需解析容器注册、返回类型、字符串常量、SPI清单与环境配置；配置绑定Profile、部署版本和Commit。
4. 通过测试插桩、Profiler、APM Trace或字节码Agent采集接收者、代理目标、顺序与频次。动态证据精确但覆盖有限，未观测的静态候选不能删除。
5. 图中记录来源、算法、行号、环境、版本与置信度；优先展示动态证实路径，再显示静态可能分支，并设置深度、环检测和节点预算。

修改前对低置信边要求证据，修改后执行覆盖目标实现的参数化或契约测试，并比较Trace。Call Graph表示可能调用，仍需结合CFG、数据流和业务终态。

**相关知识点：** 多态、动态代理、CHA、RTA、指针分析、AOP、依赖注入、运行时插桩、边置信度、Trace。

### 如何量化评估 Coding Agent 代码定位与上下文理解的准确率？

评测拆成**检索定位、证据覆盖、语义理解和端到端任务**四层，判断是否找全、理解正确并完成修改，不能用单一主观分替代。

1. 冻结仓库与Commit，以Issue/PR、历史Bug和专家任务建集，标注必需文件、Symbol、行区间、调用路径、关键事实、不变量、替代证据和验收测试。
2. 定位层报告Precision@K、Recall@K、MRR、NDCG及File/Symbol/Chunk三级命中；多文件任务计算证据完全覆盖率和无关上下文率。
3. 理解层询问入口、调用者/被调用者、状态、异常、副作用、数据来源、权限和影响范围。用图查询、测试与专家标签判分，开放解释采用Rubric、校准Judge和盲审。
4. 端到端层在相同预算下完成Bug定位、解释、修改和测试，报告完成率、首次通过、错误修改、检索轮数、Token和P95；高检索分不等于成功。
5. 按语言、仓库规模、难度、跨文件、动态调用和索引新鲜度切片，报告置信区间；真值由多人标注、仲裁和候选池化，降低标签遗漏。

线上后续读取、采纳和成功Trace仅作辅助。失败需区分召回、排序、上下文压缩、推理和工具执行责任层。

**相关知识点：** Precision@K、Recall@K、MRR、NDCG、证据覆盖率、Rubric、端到端评测、候选池化、责任归因。

### 多个子 Agent 并行探索不同模块后，如何合并/仲裁彼此的结论？

合并不能拼接摘要，应基于**统一任务契约、结构化证据和仲裁规则**；主Agent负责全局一致性，子Agent负责授权范围。

1. 为子Agent定义模块、问题、输入快照、工具、输出Schema、预算和停止条件；所有任务绑定同一仓库与Commit，避免版本差异形成伪冲突。
2. 输出统一为Claim、Evidence、Source、Commit、Confidence、Assumption和Open Question。事实附文件、行号、Trace或测试，推断与未知单独标记。
3. 主Agent按Symbol、接口和业务实体去重，写入共享证据图；接口、数据模型、调用与跨模块约束作为连接边，内部细节只保留引用。
4. 按证据仲裁：业务终态、测试和Trace优于静态推断，当前代码优于旧文档，多源一致优于单一意见。无法消解时派发定向验证或请Owner确认。
5. 合并后检查入口、契约、依赖、权限、失败路径和测试覆盖；形成统一Change Set和风险清单，再验证跨模块一致性。

并行探索默认只读；若允许修改，每个子Agent使用独立工作树，主Agent按依赖应用Patch并运行编译、契约与集成测试。评估加速比、重复率、冲突率、覆盖和完成率。

**相关知识点：** 任务契约、结构化证据、Claim-Evidence、证据图、冲突仲裁、写隔离、Change Set、全局验证、并行效率。

### 如何构建代码仓库的AST索引？

AST索引把解析结果转为**可检索节点、稳定Symbol和跨文件关系**，绑定仓库、Commit与解析器版本；不能只序列化整棵树。

1. 按语言路由到编译器、Tree-sitter或Parser，加载依赖和编译选项；排除二进制、生成物与Vendor，失败时保留错误范围。
2. 节点保存type、name、signature、起止位置、parent、scope、modifier、language、path、Commit和hash；为函数、变量生成Symbol ID。
3. 建立defines、references、imports、calls、extends、implements、contains和reads/writes边。正文按函数、类或配置块切分，代码与摘要另建Embedding。
4. 查询按节点类型、名称、注解、作用域和结构模式过滤，通过图边扩展定义、引用、实现与调用；返回源码范围和版本，供局部读取或Patch。
5. Git Diff驱动更新，哈希复用未变节点；删除旧节点与边，重算类型、继承或接口变化的邻域。新版本校验节点数、悬空引用和抽样查询后切换。

多语言采用统一Schema与扩展字段，宏、反射和动态调用标记风险，由LSP、配置或Trace补齐。监控解析覆盖率、索引滞后、P95和准确率。

**相关知识点：** AST Index、Parser、Symbol ID、源码范围、关系边、结构查询、内容哈希、增量更新、原子切换。

### Coding Agent如何根据不同任务动态调整检索策略？

Coding Agent应把检索设计为**任务感知的策略决策过程**：Planner识别任务、范围与风险，再选择数据源、查询形式、深度和停止条件。

1. 将任务分类为代码问答、缺陷定位、功能开发、重构、测试生成和依赖升级。问答优先文档与Symbol；缺陷定位扩展调用链、日志和历史提交；功能开发检索相似实现、接口契约及测试；重构重点覆盖引用图和影响域。
2. 提取仓库、模块、语言、错误栈、Symbol及Commit，将请求改写为关键词、标识符、语义查询和图遍历条件；证据不足时生成新查询。
3. 第一阶段低成本召回README、目录树、Symbol和BM25结果；第二阶段按需加入向量、AST、依赖图、Git历史及运行时Trace；高风险修改才扩大深度并使用精排。
4. Context Builder按预算选择定义、引用、调用关系和邻近测试，去重后按证据价值、时效性和Token成本排序；同一文件只补读缺失范围。
5. 策略控制器以置信度、证据覆盖率、候选边际增益和剩余预算决定继续、切换或停止。连续两轮无新增高价值证据时进入澄清或执行验证，防止无限检索。

线上记录任务类型、检索轨迹和最终成败，通过离线评测与Bandit更新路由阈值；任何自适应策略仍须遵守ACL、Commit一致性和成本上限。

**相关知识点：** 任务分类、查询改写、分阶段检索、混合召回、依赖图、上下文构建、证据覆盖率、停止条件、Bandit、检索预算。

### 检索系统如何与任务规划器（Planner）和执行器（Executor）协同工作？

三者应通过**证据驱动闭环**协同：Planner声明信息与验收条件，Retriever返回可追溯证据，Executor执行最小动作并反馈观测。

1. Planner拆解目标，为每步生成Retrieval Spec，包含意图、实体、Commit、范围、证据类型、Top-K、预算和权限；节点记录依赖与成功标准。
2. Retriever执行查询改写、混合召回、图扩展、重排和去重，返回Evidence：片段、Symbol、路径、行号、Commit、来源、分数和ACL，不能只给无出处摘要。
3. Context Builder组装最小充分上下文，维护已读范围与证据版本；Planner按覆盖率和冲突决定执行、补检索或调整计划。
4. Executor调用编辑、Shell、测试或API，动作关联步骤和证据ID；输出Diff、退出码、测试结果及错误分类。
5. Planner将观测写入状态机。可恢复错误触发定向再检索；不可恢复错误或权限不足则停止。Commit变化时重新验证相关节点。

控制面统一实施预算、超时、幂等、审计和取消传播；评测还应追踪无效轮次、证据利用率、返工率和端到端完成率。

**相关知识点：** Planner、Retriever、Executor、Retrieval Spec、Evidence对象、Context Builder、状态机、证据溯源、反馈闭环、幂等与取消。

### OpenCode如何实现百万行代码仓库检索？

百万行检索应是OpenCode的**可插拔上下文设施**：搜索和LSP即时定位，外接索引服务提供混合召回；不应虚构默认专有索引。

1. 按repo、Commit、language和module建Manifest；按Symbol与AST切块，构建BM25、Embedding、定义引用及Call Graph，保存路径、ACL和hash。
2. 路由提取标识符、错误栈、意图与结构关系，并行执行关键词、向量、LSP/AST和图检索；RRF融合后按命中、图距离和新鲜度重排。
3. 将Repo Map、签名、Top代码块、调用关系和测试逐层加入上下文；大文件按范围读取，证据不足再扩展。
4. Git Diff驱动增量解析与Embedding，更新变化块及依赖闭包；影子索引校验后原子切换，缓存键包含版本与ACL。
5. 通过Tool、Plugin或MCP接入索引，返回路径、行号、Commit、分数和来源；超时降级至Grep/LSP，不伪造完整性。

以Recall@K、MRR、Context Precision、索引新鲜度、P95、Token和任务完成率评测，并按语言、查询类型及跨模块任务切片。

**相关知识点：** 大仓检索、混合索引、LSP、AST、Call Graph、RRF、渐进式上下文、增量索引、MCP、降级。

### OpenCode如何保证代码修改安全？

安全依赖**最小权限、变更隔离、分级审批和可执行验证**；不能把模型自信或“开源”本身当作安全保证。

1. 在独立分支、worktree或沙箱中修改，限制可见目录、网络、命令和凭据；默认拒绝生产环境与Secret路径。
2. 读取可自动，写文件按路径授权，删除、外发、依赖安装、权限变更和生产操作必须确认；策略层不可由Prompt覆盖。
3. 修改前记录HEAD和工作区状态，生成后检查Diff范围、敏感信息、生成物和计划外文件，再执行编译、静态分析及相关测试。
4. 使用Commit或Patch作为交付边界；验证失败撤销本轮变更或保留隔离分支供人工检查，不覆盖用户原有未提交修改。

记录身份、工具调用、审批、Diff和验证结果。OpenCode各版本的权限与沙箱能力不同，企业部署需逐项实测并补充外层策略。

**相关知识点：** 最小权限、Sandbox、Worktree、Diff审计、Secret Scanner、审批、回滚、供应链安全。

### Coding Agent如何结合多模态能力？

多模态可让Coding Agent理解**设计稿、报错截图、架构图、性能曲线和界面状态**，但代码事实仍以仓库和工具输出为准。

图片先保存为Artifact，OCR/VLM提取组件、文字、区域和约束，再映射到代码搜索与任务计划。实现后通过截图回归、DOM/可访问性树、像素或视觉差异验证；报错截图需回到原始日志和堆栈确认。

视觉输入可能含注入和敏感信息，应隔离处理、限制工具权限并要求来源。评估视觉定位、设计还原、功能测试、无障碍和非预期Diff，避免仅凭“看起来相似”验收。

**相关知识点：** Screenshot-to-Code、Visual Regression、OCR、DOM、Accessibility、Artifact、视觉注入。
