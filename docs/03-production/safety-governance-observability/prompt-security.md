### 1. 如果检测到用户存在极端情绪，Agent如何进行干预？（千问一面）

Agent应采用**识别风险、稳定情绪、分级升级、连接现实支持并持续评估**的流程，目标是保障安全，而非医学诊断。分类模型只提供信号，策略由规则、专业审核与应急协议控制。

1. 检测自伤、伤人、绝望、告别、具体计划、时间、手段可得性及近期行为，并结合上下文判断；不能以单个关键词定性，也不能忽略隐喻风险。
2. 回复保持尊重、简洁和非评判，先确认当下安全，鼓励远离危险物、前往有人陪伴处，并联系可信人员。避免争辩、说教、承诺保密或提供危险细节。
3. 按风险分级：一般情绪提供倾听与资源；存在意念时询问是否有即时危险并建议现实支持；有明确计划、手段或正在实施时，提示立即联系当地紧急服务，并尽可能让身边人员介入。
4. 产品设置高风险响应模板、人工接管、地区化资源检索和会话优先级。紧急信息须从用户所在地权威来源动态获取，不能凭记忆猜测。
5. 日志仅保存必要的风险等级、策略命中和升级结果，限制访问与留存。通过漏报率、误报率、接管时延和事件复盘校准，避免过度升级。

| 风险级别 | 主要信号 | 处置重点 |
|---|---|---|
| 低 | 情绪低落、无伤害意念 | 共情、一般支持 |
| 中 | 出现伤害意念但无明确计划 | 安全询问、联系支持者 |
| 高 | 明确计划、手段或正在实施 | 紧急服务、人工接管 |

**相关知识点：** 危机分级、情绪识别、安全计划、Human-in-the-Loop、地区化资源、隐私最小化、误报与漏报、应急协议。

### 2. Agent安全风控体系：输入输出内容审核、工具调用权限细粒度管控、SQL/Shell沙箱隔离、敏感数据脱敏、外部接口访问黑白名单、操作审计日志（Agent高级）

安全风控应采用**输入不可信、模型无授权、工具最小权限、执行隔离、输出验证、全程审计**的零信任架构。审核、鉴权和沙箱必须位于确定性服务层。

1. 输入先做身份、租户、文件、恶意内容、Prompt Injection、密钥和PII检测；外部文档与工具回执标为不可信并隔离。原文按最小化原则留存。
2. Tool Registry声明Action、资源、读写、Schema和风险。Policy以RBAC+ABAC校验用户、Agent、环境和数据等级，签发短期最小Scope凭据；高风险须Dry Run与审批。
3. SQL使用参数化、只读副本、行列权限、语句解析、限额和回滚；Shell在无特权容器运行，限制命令、路径、资源和系统调用，且无默认外网。
4. 出站仅允许批准域名/IP、方法和数据类型，经Gateway使用mTLS及短期凭据；DLP在序列化前脱敏或阻断。输出复检安全、Schema和敏感信息。
5. 审计记录TaskID、身份、策略、参数来源、风险、审批、回执、前后状态、幂等键和副作用，并写入防篡改存储。检测越权、异常命令和外传，自动熔断。

**相关知识点：** Zero Trust、Prompt Injection、RBAC、ABAC、DLP、SQL解析、Shell Sandbox、Egress Control、短期凭据、Tamper-evident Audit。

### 3. 如何防止 Prompt Injection？

Prompt Injection不能只靠提示词消除，应采用**指令与数据隔离、最小权限、确定性Policy、验证和监测**。用户输入、网页、RAG及工具返回均视为不可信数据。

1. 固定系统规则，将外部内容置于数据边界；规范化HTML、Markdown、隐藏及编码内容并检测风险。Prompt声明不能作为授权。
2. Tool Registry按任务和权限只暴露必要工具。模型外的Policy以RBAC/ABAC校验主体、资源、动作和风险；模型声称“已授权”无效。
3. 敏感数据按字段和文档ACL过滤，系统Prompt、密钥、跨租户内容及长期凭据不进上下文。外部请求经Egress、DLP和短期令牌。
4. 写入、删除、资金、权限和生产发布使用Dry Run、参数来源、风险评分及HITL，并验证后置条件。工具回执不能改变Policy。
5. 测试直接、间接和持久化注入，覆盖网页、知识库及Memory；监控越权、异常Tool和敏感访问。高风险时降为只读、隔离或终止。

| 类型 | 入口 | 重点控制 |
|---|---|---|
| 直接注入 | 用户输入 | 指令层级、Policy |
| 间接注入 | 网页/RAG/工具结果 | 数据隔离、来源标签 |
| 持久化注入 | Memory/知识库 | 写入审核、版本与清理 |

**相关知识点：** Direct/Indirect Injection、Instruction Hierarchy、Policy Engine、Least Privilege、DLP、Egress、HITL、持久化注入。

### 4. 如何评估Agent上线后的ROI？

Agent ROI以**可归因的增量价值减去全生命周期成本**计算，并与原流程基线比较；调用量和模型分数都不是ROI。

1. 明确单位、观察期和对照组。价值包括节省工时、吞吐、收入、转化、错误减少和风险降低；每项需有财务认可的货币化规则。
2. 成本包含模型、Tool/API、计算、存储、开发、评测、集成、运维、人工审核、培训、合规和机会成本；失败、重试及接管必须计入。
3. 计算`ROI=(增量收益-增量成本)/增量成本`，同时报告Payback Period、Cost/Success、人工分钟/成功任务和边际成本。节省工时只有被重新利用或减少外包支出时才构成实际收益。
4. 使用A/B、分阶段推广或差分法控制季节、流量和政策变化；按TaskType、难度与风险切片，报告置信区间及敏感性分析。
5. 设置质量与安全护栏：完成率、满意度、缺陷逃逸、投诉、越权和事故。若收益来自降低质量或转移成本给人工，则不算有效ROI。

持续追踪模型价格、任务分布和人工流程，比较预测与实际；将一次性建设与持续运营成本分开，由产品、财务和风险共同复核。

**相关知识点：** ROI、Incremental Value、Total Cost of Ownership、Payback Period、Cost/Success、A/B Test、敏感性分析、成本归因。

### 5. 为什么企业级Agent通常采用最小权限原则？

企业Agent采用最小权限，是因为模型会**概率性决策、受非可信输入影响并自动组合工具**；权限越宽，误判或注入的爆炸半径越大。

1. Prompt Injection、错误规划、幻觉参数或Tool返回污染都可能把正常能力转为越权操作；最小权限将模型错误限制在可接受范围。
2. 用户、Agent、任务和Tool是不同主体。运行时取用户授权、Agent上限、任务委托和组织策略的交集，Agent不继承用户全部权限。
3. 权限细化到动作、资源、环境、租户、数据级别、次数和时间，例如只读指定仓库、禁止主分支。高风险能力使用JIT凭证和审批。
4. 最小权限降低误删、外泄、横向移动和供应链攻击影响，也满足职责分离、数据最小化及合规要求，便于确认受影响资源。
5. 采用RBAC基线、ABAC约束和Policy Engine，密钥由Vault按需注入且不进入模型上下文；网关、沙箱与目标系统共同强制。

最小权限是**按任务动态授予刚好足够的能力**。通过拒绝日志、权限使用率和失败分析校准，清除闲置权限并避免过度收紧。

**历史别名：** `TOOL-059`。

**验证指标：** 误报率、漏报率、策略绕过率、告警恢复时间和审计覆盖率。

**相关知识点：** 最小权限、权限交集、Prompt Injection、爆炸半径、Just-in-Time授权、职责分离、Vault、默认拒绝、纵深防御。

### 6. Agent如何防止提示词注入导致越权调用工具？

关键是建立**“文本只能提出意图，可信策略才能授权”**的边界；即使模型遵从恶意提示，工具层也必须拒绝越权动作。

1. 将系统规则、用户输入、RAG文档和Tool返回分层，外部内容标为不可信数据；其中指令不进入控制面，用户声称的身份或审批不作为证据。
2. Agent仅获得任务所需Tool，使用严格Schema与Capability；规范化路径、URL、数据库对象和资源ID，拒绝未知字段、动态代码、目录穿越和SSRF。
3. Policy Engine每次校验可信身份、Agent上限、任务委托、资源、风险和审批，默认拒绝且显式Deny优先；模型或用户内容不能改变策略。
4. 高风险读写、外发、删除和提权先Dry Run、Diff或审批，令牌绑定Tool、参数哈希、资源与TTL；参数变化重审，Hard Deny不可绕过。
5. Tool在沙箱中以短期凭证运行，限制文件、网络、速率和副作用；响应再次隔离，执行后回读终态并审计。

注入检测和模型拒绝只是附加信号。通过间接注入、编码混淆、多轮诱导、Tool返回注入和跨租户场景持续红队，对异常序列降权或熔断。

**验证指标：** 误报率、漏报率、策略绕过率、告警恢复时间和审计覆盖率。

**相关知识点：** Prompt Injection、指令数据隔离、Capability、Policy Engine、默认拒绝、参数绑定审批、沙箱、SSRF、纵深防御。

### 7. 如何限制Agent访问知识库中的敏感文档？

敏感文档应实行**摄取分类、检索前授权、最小披露和全链路审计**，不能先召回全库再依赖Prompt保密。

1. 为文档与Chunk标注TenantID、Owner、数据级别、地域、用途、角色和有效期；标签从可信DLP或内容系统继承，缺失或冲突时隔离。
2. 高敏数据使用独立索引、命名空间或物理环境及租户专属密钥；向量、元数据、缓存、备份和日志同样加密保护。
3. 验证用户和Agent身份，Policy Engine按用户权限、Agent上限、任务、租户、数据级别和审批做ABAC；服务端检索时强制过滤。
4. Security Trimming只返回所需Chunk；进入模型前脱敏PII、密钥和机密字段，限制复制、下载、外发与跨供应商传输；高风险需JIT授权。
5. 结果携带SourceID和权限血缘；缓存Key包含租户与权限，权限变化立即失效。日志仅存摘要或加密Artifact，防止二次泄露。

审计记录主体、策略、过滤数量、命中文档、导出和拒绝，对批量搜索、跨域查询告警。定期测试越权、缓存投毒、Embedding反演及撤权。

**相关知识点：** 数据分级、ABAC、Security Trimming、DLP、Tokenization、租户密钥、权限感知缓存、Embedding隐私、JIT授权。
